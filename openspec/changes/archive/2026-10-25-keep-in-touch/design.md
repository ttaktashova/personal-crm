# Design

## Context

Мотивация — в `proposal.md` (Why), требования — в `specs/`. Макет всех экранов для компьютера и телефона: https://claude.ai/artifact/H3fwWd1z31MDDyrMqBkwNW — по нему сверять вид, отступы и расположение; при расхождении с текстами спек правы спеки. Экраны макета (у каждого вариант для компьютера и `*-phone` для телефона): главная — `Main` и `Home-phone`, главная без тех, кому пора мстить, — `Home-empty*`, карточка со строкой «Как часто припоминать» — `Card*`, окна контакта — `New*` («Новый чертила», окно поверх главной) и `Edit*`. Окна истории мести (`History*`, `Record*`, `Delete-record*`) эта фича не меняет.

`interaction-history` уже влита и заархивирована (`openspec/changes/archive/2026-10-25-interaction-history/`). В коде сейчас есть:

- Таблица `contacts` (`src/db/schema.ts`): `name`, `how_we_met`, `phone`, `email`, `notes`, `created_at`, `updated_at` — и таблица `interactions` (`contact_id` → `contacts.id` с `ON DELETE CASCADE`, `occurred_on date` строкой, `summary`, индекс `(contact_id, occurred_on desc, id desc)`). Миграции `0000`–`0002` лежат в `drizzle/`; при выкатке их применяет разовый контейнер (`scripts/migrate.mjs`), все новые миграции — в одной транзакции.
- `src/lib/dates.ts`: `APP_TIME_ZONE = "Europe/Moscow"` и `todayIsoDate()` — дата `"YYYY-MM-DD"` по Москве, работает и на сервере, и в браузере.
- `src/lib/format.ts`: `pluralize`, `formatLongDate` (и `Date`, и строка `date`), `formatShortDate("2026-10-24")` → «24.10.2026».
- `src/lib/interactions.ts` (`listInteractions`) и `src/app/contacts/interaction-actions.ts` (`addInteraction`, `updateInteraction`, `deleteInteraction`), `DEFAULT_INTERACTION_SUMMARY` («Отомстил») в `src/lib/interaction-schema.ts`.
- Карточка `src/app/contacts/[id]/page.tsx`: заголовок с `ContactCardActions` (окно `EditContactDialog` с `ContactForm mode="edit"`, `DeleteContactButton`), строка «мстили …», «Добавлен … · изменён …», поля списком `dl` с разделом «Последняя месть» (`InteractionSection`) перед «Заметками», скелетон.
- Серверные действия проверяют ввод zod-схемами и после записи вызывают `revalidatePath`: ответ действия приносит свежие данные страницы. Этот приём сохраняем.
- `next.config.ts`: `cacheComponents: true`. Данные из базы читаются внутри `Suspense`; текущее время в серверном компоненте можно брать только после обращения к динамическим данным. Перед кодом — читать гайды в `node_modules/next/dist/docs/` (правило `AGENTS.md`).
- UI: shadcn/ui в стиле `base-nova` поверх `@base-ui/react`; `select` нет. На главной уже есть растерянный кот `CatConfused` (`src/components/cat-confused.tsx`) на токенах `--cat*`.

## Goals / Non-Goals

**Goals:**

- Один SQL-запрос считает, кому пора мстить, и сразу сортирует.
- Правила срока — календарные, «сегодня» — одна точка правды (`todayIsoDate()`).
- Без новых npm-библиотек.

**Non-Goals:**

- Уведомления и напоминания вне приложения (в продуктовой идее — «Не делать»).
- Показ частоты в общем списке контактов, фильтры по ней.
- Переименование кода под надписи: имена в коде (`contact_frequency`, `keep-in-touch`, `markContacted`, `stopReminders`) остаются нейтральными английскими.
- Настройка часового пояса: пользователь один, пояс зашит константой.

## Decisions

### 1. Модель данных

```
contacts
  …                  (как сейчас)
  contact_frequency  contact_frequency NULL      ← новое

enum contact_frequency: 'week' | 'month' | 'quarter' | 'year'     (NULL = «Не задано»)
```

- **Частота — enum, NULL = не задано.** Альтернативы: число дней (отклонено: месяц и год не равны фиксированному числу дней, а спека требует календарных), хранимая «дата следующей мести» (отклонено: её пришлось бы пересчитывать при каждом изменении истории).
- **Последняя месть по-прежнему не хранится в `contacts`**, а берётся из `interactions` (`max(occurred_on)`) — индекс из `interaction-history` это покрывает.
- Смена частоты (в том числе «Простить») — изменение карточки и обновляет `updated_at`. «Отомстил» на главной — запись о мести и `updated_at` не трогает (как все записи в `interaction-history`).
- Одна миграция `0003_add_contact_frequency` (`pnpm db:generate --name=add_contact_frequency`): `CREATE TYPE` и `ALTER TABLE … ADD COLUMN` с NULL. Существующие данные не меняются: у всех контактов «Не задано».

### 2. Форматы

`formatDueLabel(dueOn, today)` в `src/lib/format.ts` → «пора сегодня» / «пора со вчера» / «пора с 01.10.2026» (через `formatShortDate`). «Вчера» — это `today` минус один календарный день; обе даты — строки `YYYY-MM-DD` по Москве, поэтому сравнение не зависит от пояса сервера.

Подписи частот («Раз в неделю» …, «Не задано») и список значений — в `src/lib/contact-frequency.ts`, общий для формы, карточки и главной.

### 3. Расчёт «пора мстить» — один SQL-запрос

`src/lib/keep-in-touch.ts`, `listDueContacts(today)`:

```sql
select c.id, c.name, c.contact_frequency, last.occurred_on as last_on,
       (last.occurred_on + case c.contact_frequency
          when 'week' then interval '7 days'  when 'month' then interval '1 month'
          when 'quarter' then interval '3 months' when 'year' then interval '1 year' end)::date as due_on
from contacts c
left join lateral (select max(occurred_on) as occurred_on
                   from interactions i where i.contact_id = c.id) last on true
where c.contact_frequency is not null
  and (last.occurred_on is null or <due_on> <= :today)
order by (last.occurred_on is null) desc, due_on asc, c.name collate "ru-RU-x-icu", c.id
```

Порядок по спеке: сначала те, кому ещё не мстили (`due_on` у них пустой), потом по `due_on` от раннего к позднему, а при равном сроке — имя по алфавиту в той же ICU-коллации, что и общий список; `id` — последний разбор ничьей, чтобы порядок не прыгал. `today` приходит параметром из `todayIsoDate()`, а не через `current_date` Postgres (у того пояс сессии).

`date + interval '1 month'` в Postgres сам обрабатывает конец месяца (31.01 → 28.02), это и требует спека. Альтернатива — считать в JS по всем контактам — отклонена: пришлось бы тянуть все контакты с последними датами и самим реализовывать календарную арифметику.

### 4. Проверка ввода

`contactInputSchema` получает `contactFrequency`: одно из значений enum или `null`. Пункт «Не задано» в форме отправляет пустую строку → схема превращает её в `null`.

### 5. Серверные действия

Результаты в том же стиле, что сейчас (`{ status: … }`).

- `src/app/contacts/actions.ts`: `createContact` / `updateContact` сохраняют `contactFrequency`; новое `stopReminders(contactId)` — `contact_frequency = null`, `updated_at = now()` (контакта нет → `not-found`, как в `updateContact`); `revalidatePath("/")` и карточки.
- `src/app/contacts/interaction-actions.ts`: новое `markContacted(contactId)` — запись на `todayIsoDate()` (дата берётся на сервере, не из браузера) с `DEFAULT_INTERACTION_SUMMARY`, тем же способом вставки, что `addInteraction` (контакта нет → `not-found`). Кроме карточки перепроверяет главную: `revalidatePath("/")`.
- `addInteraction`, `updateInteraction` и `deleteInteraction` из `interaction-history` начинают перепроверять и главную (`revalidatePath("/")`): после правки истории в карточке блок «Пора мстить» должен быть свежим.

### 6. Карточка и форма

- **Карточка** — в `dl` строка «Как часто припоминать» после «Почты», перед «Последней местью»: подпись из `contact-frequency.ts`, «Не задано» показывается как значение, а не «не указано». Скелетон получает ещё одну строку.
- **`ContactCardActions`** передаёт окну редактирования и текущую частоту.
- **`ContactForm`** — одна форма для окон «Новый чертила» и «Редактировать контакт» — получает поле «Как часто припоминать»: shadcn `select` с `name`, значение попадает в `FormData`. Стоит между «Почтой» и «Заметками», как в макете обоих окон (`New*`, `Edit*`); по умолчанию «Не задано». Кнопка списка выглядит как поля рядом: на всю ширину, высота 44 px, стрелка вниз справа.

### 7. Главная: блок «Пора мстить»

Отдельный серверный компонент `DueContacts` в своём `Suspense` между заголовком страницы и поиском: блок и список грузятся независимо. Сервер отдаёт весь список; внутри — клиентский `DueContactsList`: имя-ссылка, «частота · подпись срока» (`formatDueLabel` или «ещё не мстили») и две кнопки.

- **Вид — по макету `Main` и `Home-phone`.** Блок — карточка, как группы общего списка (`rounded-card border bg-card`), с заголовком «Пора мстить» (`h2`, `font-display`, 20 px на компьютере, 19 px на телефоне) и строками через линию. В строке имя — подчёркнутая ссылка (линия цвета `border-strong`), под ним мелким серым «частота · срок»; срок — цветом акцента (`text-primary`, `font-medium`), в том числе «ещё не мстили». Отступы: 12 px от заголовка страницы, до поиска — 24 px на компьютере и 20 px на телефоне.
- **Первые пять.** Клиент хранит `expanded` (по умолчанию `false`) и показывает `expanded ? all : all.slice(0, 5)`. Если людей больше пяти и список свёрнут — последней строкой кнопка «+ещё N людишек» (`pluralize(n, ["людишка", "людишки", "людишек"])`, `aria-expanded="false"`); нажатие ставит `expanded = true`, строка исчезает. «Свернуть» нет. После «Отомстил» / «Простить» сервер присылает список без этого человека, и в свёрнутом виде на его место поднимается шестой. Строка «+ещё …» — кнопка на всю ширину, высота 52 px, цвет акцента, полужирный 15 px, после текста стрелка вниз (`ChevronDownIcon`); на компьютере выровнена влево, на телефоне — по центру.
- **Кнопки.** Одна кнопка на действие, вид зависит от ширины. От 640 px (`sm:`) — текст: «Отомстил» красная (`variant="default"`), «Простить» с рамкой (`variant="outline"`); высота 36 px, скругление 10 px, шрифт 13 px — как кнопка «Отомстил» в карточке (`sm:h-9 sm:rounded-lg sm:px-3.5 sm:text-caption` в `InteractionSection`), а не `size="sm"` (там 32 px и 12 px). Уже 640 px — иконка 44×44 со скруглением 12 px (`CheckIcon` на красном фоне и `BellOffIcon` с рамкой из `lucide-react`) с подсказкой shadcn `tooltip`. Текст и иконка лежат в одной кнопке, лишнее скрыто через `hidden sm:inline` / `sm:hidden`. `aria-label` — «Отомстил: <имя>» / «Простить: <имя>» всегда. На телефоне иконки стоят справа от имени, в одну строку.
- Каждая кнопка вызывает своё серверное действие в `useTransition`, на время выполнения кнопки строки неактивны; ответ действия приносит свежий список, и строка пропадает. Ошибка — `toast.error`, как в существующих компонентах. Ответ `not-found` (контакт удалили в другой вкладке) — `toast.error("Этот контакт не найден. Возможно, его удалили.")` и `router.refresh()`, чтобы строка пропала.

Список пустой → вместо блока `DueContacts` рисует компактную карточку «Пока некому мстить» (макет `Home-empty*`): фон и рамка как у блока, внутри в одну строку картинка `CatSad` (`src/components/cat-sad.tsx`) и надпись «Пока некому мстить» (`h2`, `font-display`, 18 px на компьютере, 17 px на телефоне, без переноса). Котик — 64×57 px на компьютере и 56×50 px на телефоне, до надписи 16 / 14 px, поля карточки 12×20 / 10×16 px. Рисунок — тот, что в макете `Home-empty`: голова и уши как у `CatConfused`, глаза смотрят вниз из-под опущенных век, слеза, рот грустной дугой. Цвета — только токенами: `--cat`, `--cat-eye`, `--cat-glint`, `--cat-pink`, контур — `--border`, слеза — `--foreground`. `aria-hidden`, потому что смысл передаёт надпись. Карточка показывается и тогда, когда контактов нет совсем.

`today` берётся после чтения `searchParams` / данных, чтобы не нарушить правило `cacheComponents` про текущее время.

### 8. Тестовые данные

`scripts/seed-data.ts` примерно четверти контактов задаёт случайную частоту (записи о мести к датированным заметкам он уже создаёт после `interaction-history`). Так на свежей базе есть что проверить в «Пора мстить». Существующую локальную базу seed по-прежнему не трогает.

### 9. Компоненты shadcn

`pnpm dlx shadcn@latest add select` (`tooltip` и `dialog` уже добавлены). После добавления проверить `package.json`: новых зависимостей быть не должно (всё строится на `@base-ui/react`). Если CLI потребует новую библиотеку — остановиться и обсудить с владельцем.

## Risks / Trade-offs

- [Пользователь в другом часовом поясе увидит «сегодня» по Москве] → Пользователь один и в Москве; пояс — одна константа.
- [Блок «Пора мстить» станет длинным, если задать частоту многим контактам без истории] → Видно первых пятерых, остальные — по «+ещё N людишек».
- [Иконки на телефоне менее очевидны, чем текст] → Выбраны привычные символы (галочка — сделано, перечёркнутый колокольчик — не напоминать), у кнопок подсказка и `aria-label` с именем; на компьютере остаётся текст.
- [«Простить» без подтверждения: случайное нажатие сбросит частоту] → Частоту легко задать снова в окне редактирования; записи о мести не трогаются.

## Migration Plan

1. PR в `main` → CI собирает образ → `deploy.sh` применяет `0003` → стартует новое приложение → smoke `/health`.
2. Проверка после выкатки: у всех контактов «Как часто припоминать» — «Не задано», на главной карточка «Пока некому мстить»; задать частоту контакту с давней записью — он появляется в «Пора мстить».
3. Откат — только вручную, по README. Миграция только добавляет колонку с NULL, поэтому предыдущий образ работает с новой базой и просто не видит частоту.
