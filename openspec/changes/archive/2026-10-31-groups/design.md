# Design

## Context

Мотивация — в `proposal.md` (Why), требования — в `specs/`. Что есть в коде сейчас:

- **База** (`src/db/schema.ts`): таблицы `contacts` и `interactions`, миграции `0000`–`0003` в `drizzle/`. Разовые переносы данных пишутся отдельной SQL-миграцией (`0002_copy_interactions_from_notes.sql`). При выкатке все новые миграции применяет `scripts/migrate.mjs` разовым контейнером, в одной транзакции.
- **Запросы** идут только через `runQuery(label, db => …)` (`src/db/index.ts`). Ошибку он заменяет на `DatabaseError`, где остаются только `code`, `table`, `column` и `constraint`. Код уникальности (`23505`) и имя индекса из неё прочитать можно.
- **Русские правила:** сортировка `collate "ru-RU-x-icu"`. Сравнение без регистра — `replace(lower(name collate "ru-RU-x-icu"), 'ё', 'е')`, то же делает `normalizeForSearch` в браузере. Своя `lower()` у базы на локали `en_US.utf8` с провайдером libc для кириллицы ненадёжна, поэтому везде ICU. Проверено на локальном Postgres 18: уникальный индекс по этому выражению не пускает «теннис» при «Теннис» и «Елка» при «Ёлка».
- **Главная** (`src/app/page.tsx`): `DueContacts` и `Directory` каждый в своём `Suspense`. `Directory` разбирает `?page=`, `?q=`, `?size=`, `?added=` и вызывает `listContactsPage`. Ссылки на список строит только `buildListHref` (`src/lib/pagination.ts`). Адрес, куда вернуться из карточки, запоминается во вкладке (`src/lib/list-return.ts`) тоже через него.
- **«Пора мстить»:** `listDueContacts(today)` (`src/lib/keep-in-touch.ts`), один SQL-запрос.
- **Форма контакта** (`src/components/contact-form.tsx`) читает поля из `FormData` и проверяет их zod-схемой `contactInputSchema`. Сохраняют её серверные действия `createContact` и `updateContact` (`src/app/contacts/actions.ts`): они сами пишут в базу и вызывают `revalidatePath`.
- **Окно с несколькими видами внутри** уже есть: `interaction-history-dialog.tsx` (`view: list | add | edit | confirm-delete`).
- **Next.js 16** с `cacheComponents: true`. Перед кодом читать гайды в `node_modules/next/dist/docs/` (правило `AGENTS.md`).
- **UI:** shadcn/ui `base-nova` поверх `@base-ui/react` 1.8.0, в нём есть `Combobox` с выбором нескольких значений. Компонента `combobox` в `src/components/ui/` пока нет. `Badge` есть.
- **Тестов в проекте нет.** Локальная база — Postgres 18 в Docker (`personal-crm-postgres`). В локальном `.env` задан `DATABASE_URL`, и `getDatabaseUrl()` берёт его первым.

## Goals / Non-Goals

**Goals:**

- Группы — отдельные таблицы со связями. Удаление контакта или группы само чистит связи.
- Повторы названий не пускает база, а не только интерфейс.
- Сохранение контакта с группами — одна транзакция.
- Фильтр по группе — ещё одно условие в существующих запросах списка и «Пора мстить», а не отдельные запросы.
- Логика групп в функциях `src/lib/`, которые можно тестировать без Next.js. Серверные действия только проверяют ввод, вызывают эти функции и `revalidatePath`.
- Первые автотесты проекта (Vitest) — на настоящей базе, без моков.

**Non-Goals:**

- Фильтр сразу по нескольким группам, цвета и иконки групп, свой порядок групп.
- Метки групп в строках блока «Пора мстить». Метки в карточке не кликаются.
- Запоминание выбранной группы между открытиями главной.
- e2e (Playwright) и CI. Автотесты на старые фичи.
- Изменения таблицы `contacts`.

## Decisions

### 1. Модель данных

```
groups
  id          integer identity PK
  name        text NOT NULL                        как ввели, без пробелов по краям
  created_at  timestamptz NOT NULL DEFAULT now()
  UNIQUE INDEX groups_name_key ON (replace(lower(name collate "ru-RU-x-icu"), 'ё', 'е'))

contact_groups
  contact_id  integer NOT NULL → contacts.id ON DELETE CASCADE
  group_id    integer NOT NULL → groups.id   ON DELETE CASCADE
  PRIMARY KEY (contact_id, group_id)               группы одного человека, без повторов
  INDEX contact_groups_group_id_contact_id_idx ON (group_id, contact_id)   фильтр по группе
```

Почему так:

- **Отдельная таблица связей, а не массив `group_ids int[]` в `contacts`.** Связи с внешними ключами сами пропадают при удалении группы или контакта. У массива нет внешних ключей: удалённая группа оставалась бы в массивах, и её пришлось бы вычищать руками.
- **Группа — строка в таблице, а не текстовая метка у контакта.** Переименование меняет одну строку, а не все контакты. Пустая группа может существовать.
- **Уникальность по выражению, а не отдельная колонка `name_key`.** Колонку пришлось бы держать в согласии с `name` при каждой записи. В Drizzle индекс описывается как `uniqueIndex("groups_name_key").on(sql\`…\`)`.
- **`updated_at` у группы не нужен:** нигде не показывается.

Типы: `Group`, `NewGroup`. Связь контакта с группой наружу не отдаётся отдельным типом: у контакта есть `groups: { id, name }[]`.

### 2. Миграции

- `0004_create_groups.sql` — `pnpm db:generate` по схеме. Проверить, что drizzle-kit записал индекс с тем же выражением.
- `0005_add_default_groups.sql` — `drizzle-kit generate --custom`: `insert into groups (name) values ('Аналитики'), ('Друзья'), ('Знакомые'), ('Семья'), ('Теннис') on conflict do nothing`.

Обе миграции применяются вместе в одной транзакции. Если что-то упадёт, не будет ни таблиц, ни групп, и новый образ не стартует (правило CLAUDE.md). Таблица `contacts` не меняется, поэтому прежний образ с новыми таблицами работает как раньше.

### 3. Название группы — одна схема

`groupNameSchema` (`src/lib/group-schema.ts`, zod): `trim`, `min(1, "Укажите название группы")`, `max(50, "Слишком длинное название: не больше 50 символов")`. Ею пользуются форма контакта (новые названия), окно «Группы» и серверные действия.

Повторы:

- **В браузере** (поле «Группы») совпадение ищется по `normalizeForSearch(name.trim())`. Это решает, показать ли «Создать группу «…»» или предложить существующую.
- **На сервере решает база.** Ошибка `23505` с `constraint === "groups_name_key"` из `DatabaseError` превращается в `{ status: "invalid", fieldErrors: { name: "Такая группа уже есть" } }`. Любая другая ошибка базы уходит дальше, как сейчас.

Предварительный `select` перед вставкой не нужен: между ним и вставкой группу может создать другая вкладка, а индекс всё равно сработает.

### 4. Функции групп — `src/lib/groups.ts` (`server-only`)

- `listGroups()` — все группы по алфавиту с числом людей: `left join contact_groups`, `count`. Обёрнута в React `cache`: на одном запросе её читают строка фильтра, проверка `?group=`, окно «Группы» и поле «Группы».
- `createGroup(name)`, `renameGroup(id, name)` → `created | renamed | duplicate | not-found`.
- `deleteGroup(id)` → `deleted | not-found`. Связи удаляет `ON DELETE CASCADE`. `contacts.updated_at` не трогается.
- `listContactGroups(contactIds)` — группы нескольких контактов одним запросом: `where contact_id in (…)`, по алфавиту. Ею пользуются карточка (один id) и страница списка (id всей страницы).
- `setContactGroups(tx, contactId, { groupIds, newGroupNames })` — внутри транзакции сохранения контакта, по шагам:
  1. `insert into groups (name) values … on conflict do nothing` для новых названий;
  2. `select id from groups where <выражение> in (<нормализованные названия>)` — так находится и только что созданная, и уже существующая группа (сценарий «Ту же группу успели создать»);
  3. `delete from contact_groups where contact_id = …`;
  4. `insert into contact_groups (contact_id, group_id) select …, id from groups where id in (<groupIds ∪ найденные>)`.

  Шаг 4 берёт только существующие группы. Группа, которую удалили, пока окно было открыто, просто не попадает в связи, ошибки нет.

### 5. Сохранение контакта — в `src/lib/contacts.ts`

Запись в базу переезжает из `actions.ts` в `insertContact(input)` и `updateContactById(id, input)`. Обе работают в одной транзакции `runQuery("…", db => db.transaction(tx => …))`: сначала поля контакта, потом `setContactGroups`. Если транзакция упала, нет ни новых групп, ни изменений контакта (сценарий «Сохранение не удалось»). `createContact` и `updateContact` в `actions.ts` проверяют ввод, вызывают эти функции и `revalidatePath`. Возвращают они то же, что сейчас.

`contactInputSchema` получает два поля:

- `groupIds: z.array(<id>).max(100)`, повторы убираются;
- `newGroupNames: z.array(groupNameSchema).max(20)`, повторы без регистра и «ё» убираются.

Ошибка в названии показывается у поля «Группы» (`fieldErrors.groups`). Полей `name` и остальных это не меняет. Пределы `100` и `20` — защита от мусорного запроса, а не продуктовое правило: в интерфейсе до них не дойти.

`updated_at` меняется при каждом «Сохранить», как сейчас. Значит, меняется и когда поменяли только группы (спека `contact-groups`, «Группы и дата «изменён»»).

### 6. Фильтр по группе — `?group=<id>`

- **В адресе id, а не название:** адрес не ломается при переименовании, и в нём нет кириллицы.
- **`buildListHref({ group, q, page, size })`** — параметр `group` идёт первым, `null` в адрес не пишется. Отсюда же ссылки строки групп, переключателя страниц, выбора количества, поиска и возврата из карточки. Значит, группа сохраняется везде, где нужно, без отдельного кода. Ссылка строки групп ставит `page: 1` и сохраняет `q` и `size`.
- **Проверка группы:** `resolveGroupFilter(param, groups)` — `parseId(firstValue(param))`. Если такой группы нет в `listGroups()`, возвращается `null` («Все»). `Directory` и `DueContacts` вызывают её независимо, а `cache` у `listGroups` даёт один запрос к базе.
- **`listContactsPage({ page, pageSize, words, groupId })`.** Когда группа выбрана, все подсчёты и выборка идут по `exists (select 1 from contact_groups cg where cg.contact_id = contacts.id and cg.group_id = $groupId)`. Возвращает:
  - `totalCount` — людей в группе (для «12 контактов» и «… из 12»);
  - `matchedCount`;
  - `allCount` — всех контактов, чтобы отличить «Здесь пока никого нет» (контактов нет совсем) от «В группе «…» пока никого нет»;
  - `contacts[i].groups` — одним запросом `listContactGroups` по id страницы.
- **`listDueContacts(today, groupId)`** — то же условие `exists` в подзапросе `where`.
- **После «Добавить черта»** `router.replace("/?added=…")` уже без группы, менять ничего не нужно.

`findContactPage` не меняется: новый контакт ищется во всём списке.

### 7. Интерфейс

- **Строка групп** — `src/components/group-filter.tsx`, серверная. Состоит из `nav aria-label="Группы"`, в нём ссылки `next/link` «Все» и группы, у выбранной `aria-current="true"`. Справа, вне прокручиваемой части, кнопка «Группы» (клиентская, открывает окно). На телефоне — `flex-nowrap overflow-x-auto`, на компьютере — `sm:flex-wrap`. Ссылки высотой 44 px на телефоне. Стоит в `page.tsx` между заголовком и «Пора мстить», в своём `Suspense` со скелетоном той же высоты. Переход по ссылке — обычная навигация, «Назад» работает сам.
- **Окно «Группы»** — `src/components/groups-dialog.tsx` по образцу `interaction-history-dialog.tsx`: `view: list | rename | confirm-delete`. Действия — в `src/app/contacts/group-actions.ts`: `createGroup`, `renameGroup`, `deleteGroup`. Каждое вызывает `revalidatePath("/")` и `revalidatePath("/contacts/[id]", "page")`: после переименования или удаления метки в открытых карточках не должны быть старыми. Сигнатуру `revalidatePath` с типом маршрута сверить с гайдом Next 16. Список групп окно получает пропсом от серверной части главной, ответ действия приносит свежий. При `not-found` — toast «Эта группа не найдена. Возможно, её удалили.» и возврат к списку.
- **Поле «Группы»** — `src/components/group-picker.tsx` на shadcn `combobox` (Base UI `Combobox`, `multiple`, метки-чипы):
  - варианты — `listGroups()` плюс выбранные новые названия;
  - если вписанный текст после `normalizeForSearch` не совпадает ни с одной группой и проходит `groupNameSchema`, в конце списка пункт «Создать группу «…»». Если не проходит по длине — вместо пункта текст ошибки;
  - Enter в поле выбирает подсвеченный пункт и не отправляет форму. Ctrl+Enter, как и сейчас, сохраняет;
  - `ContactForm` хранит выбор в состоянии (`{ groupIds, newGroupNames }`) и добавляет его к значениям из `FormData`.

  Список групп для поля передаётся пропсом в `NewContactDialog` (главная) и `ContactCardActions` → `EditContactDialog` (карточка). Каждая страница читает `listGroups()` сама.
- **Карточка:** строка `dl` «Группы» после «Откуда знакомы». В ней `Badge` по алфавиту, все. Если групп нет — «не указано», как у `TextField`. Начальные значения окна редактирования получают `groupIds` контакта. Скелетон карточки получает ещё одну строку.
- **Строка списка:** под «Откуда знакомы» строка `Badge` — первые три группы и `+N`. Её нет, если групп нет. Длинное название обрезается многоточием (`max-w` и `truncate`). Полное название — в `title`.
- **Пустая группа:** в `ContactDirectory` ветка `totalCount === 0 && groupId !== null` с текстом из спеки. «Здесь пока никого нет» — только при `allCount === 0`.
- Все цвета и отступы — через токены, как у существующих `Badge` и кнопок. Новых токенов не нужно.

### 8. Тесты — Vitest на настоящей базе

- **Зависимость:** `vitest` в `devDependencies`. Сейчас последняя стабильная — 5.0.5 (проверено 31.10.2026), перед установкой проверить ещё раз. Команда `pnpm test` → `vitest run`. Других библиотек нет: `@` и `server-only` настраиваются через `resolve.alias` в `vitest.config.ts`. `server-only` заменяется пустым файлом `src/test/server-only.ts`: вне `react-server` он нарочно бросает ошибку.
- **Своя база.** `src/test/database-url.ts` берёт `getDatabaseUrl()` (после `loadEnvConfig`, как `scripts/seed.ts`) и меняет имя базы на `<имя>_test`. Если имя не кончается на `_test`, тесты не запускаются: это защита основной базы. Сам `.env` агент не читает, его читает код.
- **`globalSetup`** пересоздаёт `<имя>_test` (`drop database … with (force)`, `create database`) и применяет миграции из `drizzle/` мигратором Drizzle. `vitest.config.ts` кладёт тестовый адрес в `test.env.DATABASE_URL`, поэтому обычный `src/db/index.ts` в тестах подключается к тестовой базе.
- **Перед каждым тестом** `resetDatabase()`: `truncate contacts, groups restart identity cascade`. Стартовые группы при этом тоже стираются, каждый тест сам создаёт нужные данные. Тест «Стартовые группы» создаёт свою временную базу, применяет миграции, проверяет её и удаляет.
- **`fileParallelism: false`:** все файлы работают с одной базой по очереди.
- **Что проверяется автотестом:** сценарии спек, где результат виден в данных — что вернули функции `src/lib/` и что лежит в базе. Сюда входят схемы проверки, `buildListHref` и `resolveGroupFilter`, функции групп, списка и «Пора мстить». Серверные действия не тестируются напрямую: им нужен рантайм Next (`revalidatePath`), а вся их логика — в проверенных функциях.
- **Что пока руками:** сценарии про вид экрана (окна, метки, фокус, прокрутка, телефон). В `tasks.md` они собраны отдельным списком для будущих e2e.

### 9. Тестовые данные

`scripts/seed.ts` после вставки контактов читает существующие группы. Если их нет, группы пропускаются. Каждому контакту генератор из `seed-data.ts` даёт от 0 до 3 групп, примерно 60 % получают хотя бы одну. Генератор тот же детерминированный. Связи вставляются пачками, в той же транзакции.

## Risks / Trade-offs

- **[shadcn `combobox` потянет новые npm-зависимости]** → после `pnpm dlx shadcn@latest add combobox` проверить `package.json`. Если появилось новое — остановиться и спросить владельца.
- **[drizzle-kit запишет выражение индекса иначе, чем ожидаем, или не сгенерирует его]** → проверить SQL `0004` глазами и тестом «Другой регистр» / «Буква «ё»». Если Drizzle не справится, дописать индекс SQL-ом в `0004`.
- **[Тесты по ошибке пишут в основную базу]** → имя базы обязано кончаться на `_test`, иначе отказ. `DATABASE_URL` для тестов задаётся в `vitest.config.ts`, а не берётся из окружения как есть.
- **[Пул соединений `postgres` держит процесс тестов]** → если Vitest не завершается сам, в `src/test/` закрывать клиент в `afterAll` или поставить `idle_timeout` для тестового адреса.
- **[Метки в строке делают список выше]** → строка меток только у тех, у кого есть группы, не больше трёх меток и `+N`.
- **[Много групп в строке фильтра на телефоне]** → прокрутка вбок, кнопка «Группы» вне прокрутки. На компьютере перенос строк. Предел числа групп не ставим.
- **[Сценарии про вид экрана пока без автотестов]** → ручная проверка по списку в `tasks.md`. Список станет основой e2e.
- **[Переименование группы меняет метки в чужой открытой вкладке не сразу]** → как и с остальными данными: свежие данные — при следующем запросе страницы.

## Migration Plan

1. PR → merge в `main` → CI собирает образ → на сервере разовый контейнер применяет `0004` и `0005`, потом стартует новый образ → smoke `/health`.
2. После выкатки на проде пять групп, все люди без групп (сценарий «Прежние контакты»).
3. Откат — только вручную, командой из README. Прежний образ не знает о `groups` и `contact_groups` и работает как раньше. Таблицы и группы остаются в базе: при новой выкатке миграции не повторяются.
