# Tasks

Как работаем:

- **Сначала тест.** Пишем тест, запускаем `pnpm test` и видим, что он красный, причём по нужной причине: нет функции или результат не тот, а не опечатка в самом тесте. Потом пишем код, и тест становится зелёным. Задача «тесты …» закрыта, когда тесты написаны и красные. Задача «код …» закрыта, когда они зелёные.
- **Vitest работает с базой `<имя>_test`** в локальном контейнере Postgres (design.md §8). Перед `pnpm test` должен быть запущен `docker compose up -d`.
- **Сценарии про вид экрана** проверяем руками на `pnpm dev`, на ширине 1280 и 375 px (DevTools). Автотестов на них пока нет, их список — в конце файла, для будущих e2e.
- **Для ручных проверок** нужна временная база с тестовыми людьми в группах: `createdb` рядом с `personal_crm` в локальном контейнере, `pnpm db:migrate` и `pnpm db:seed` в неё, запуск `DATABASE_URL= POSTGRES_DB=<временная> pnpm dev` из Git Bash. Если не очистить `DATABASE_URL`, запуск возьмёт основную базу из `.env`. Сначала убедиться, что открылась именно временная база: на главной должен быть её счётчик. Основную локальную базу не удалять.
- **Перед кодом на Next.js** прочитать нужный гайд в `node_modules/next/dist/docs/` (правило `AGENTS.md`).
- **После каждой группы** запустить `pnpm typecheck`, `pnpm lint` и `pnpm test`, всё зелёное.
