# Proposal

## Why

Когда запрос к базе не удаётся, библиотека Drizzle кладёт в текст ошибки сам запрос и все переданные в него значения, а Next.js пишет этот текст в журнал сервера. Например, если база недоступна в момент сохранения контакта, в журнале оказываются имя, «откуда знакомы», телефон, почта и заметки. При сбое записи о мести туда же попадает текст записи. Журнал хранится на сервере. Кроме того, при красном smoke выкатка выводит последние 50 строк журнала приложения в лог GitHub Actions, а репозиторий публичный, и этот лог может увидеть кто угодно. Черный список — личные данные, им не место в журналах.

## What Changes

- **В журнале приложения нет данных контактов.** При любом сбое запроса к базе в журнал пишется короткая запись: какой запрос не удался (например, добавление контакта), код ошибки и, если база их назвала, имена таблицы, поля и ограничения из схемы. Имени, «откуда знакомы», телефона, почты, заметок, текста записи о мести и слов поиска в записи нет. Нет и текста самого запроса, и пояснений базы к ошибке: в них бывают значения строк.
- **Не только сохранение.** То же правило действует для удаления, «Отомстил», «Простить», для показа главной и карточки и для проверки `/health`. На главной в запрос к базе уходят слова поиска и имя только что добавленного контакта, поэтому сбой при показе страницы тоже писал бы их в журнал.
- **Журнал выкатки без данных.** Если при выкатке падают миграции, в лог GitHub Actions пишется такая же короткая запись. Сейчас туда попала бы ошибка базы целиком, а для миграций, которые переносят данные (как перенос заметок в историю мести), в ней бывает строка таблицы со значениями. Выкатка, как и сейчас, останавливается, новый образ не стартует.
- **Не меняется:** что видит пользователь. При сбое окна остаются открытыми с введёнными данными, сообщения прежние, при сбое показа страницы — прежняя страница «Не получилось загрузить данные». База, миграции и зависимости не меняются.

## Capabilities

### New Capabilities

- `error-logging`: что система пишет в журнал приложения и в журнал выкатки при сбое запроса к базе и чего она туда писать не должна.

### Modified Capabilities

Нет. Поведение окон и страниц при сбое уже описано в спеках `contact-list`, `contact-card`, `interaction-history`, `keep-in-touch` и не меняется.

## Impact

- **Код приложения:** все запросы к базе идут через одну обёртку в `src/db/`. Она перехватывает ошибку и заменяет её безопасной. Затронуты `src/app/contacts/actions.ts`, `src/app/contacts/interaction-actions.ts`, `src/lib/contacts.ts`, `src/lib/interactions.ts`, `src/lib/keep-in-touch.ts`, `src/app/health/route.ts`.
- **Миграции при выкатке:** `scripts/migrate.mjs` ловит ошибку и печатает короткую запись вместо ошибки целиком.
- **Выкатка:** `deploy/deploy.sh` и workflow не меняются. Вывод журнала приложения в лог GitHub Actions при красном smoke остаётся, но данных в нём больше не будет.
- **База данных, миграции, зависимости:** без изменений. Новых библиотек нет.
- **README:** коротко дописать, что в журнал не пишутся данные контактов и что остаётся в записи об ошибке.

## Open Questions

Решения, которые я предложил сам (технические, интерфейс не меняют). Владелец согласовал их 31.10.2026:

1. **Все запросы к базе, а не только сохранение.** Причина та же, и исправление одно на всё. Слова поиска и имя нового контакта иначе остались бы в журнале при сбое главной.
2. **Текст запроса тоже не пишем.** Значений в нём нет, но правило «только коды и имена из схемы» проще проверить, и оно не сломается, если кто-то позже вставит значение прямо в запрос. Какой запрос упал, запись называет сама.
3. **Старые записи в журнале сервера.** Если сбои уже были, данные могут лежать в журнале нынешнего контейнера приложения. При выкатке контейнер пересоздаётся, и его журнал удаляется вместе с ним, если Docker на сервере хранит журналы по умолчанию. Проверить с сервера сам я не смог: доступ на чтение с сервера мне не разрешён. После выкатки дам команду, которая покажет, остались ли такие записи. Если остались, сам ничего удалять не буду — спрошу вас.
4. **Лог GitHub Actions.** Красного smoke ещё ни разу не было (все 11 выкаток зелёные), значит, в публичный лог журнал приложения не попадал.

Не входит в это изменение. Решение владельца 31.10.2026: не берём.

5. **Слова поиска в журнале nginx.** Поиск лежит в адресе (`/?q=петров`), а nginx записывает адрес каждого запроса в свой журнал доступа. Это происходит при каждом поиске, а не только при сбое.
6. **Терминал при `pnpm dev`.** В режиме разработки Next.js печатает в терминал каждый вызов сохранения вместе с введёнными значениями. Это только на вашем компьютере и никуда не сохраняется.
