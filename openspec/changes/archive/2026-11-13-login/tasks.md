# Tasks

Как работаем:

- **Сначала тест.** Пишем тест, запускаем и видим, что он красный по нужной причине: нет функции, нет страницы или результат не тот, а не опечатка в самом тесте. Потом код — тест зелёный. Задача «тесты …» закрыта, когда тесты написаны и красные. Задача «код …» закрыта, когда они зелёные.
- **Перед `pnpm test` и `pnpm test:e2e`** запущен `docker compose up -d` — Postgres и, с группы 1, Mailpit. Vitest работает с базой `<имя>_test`, e2e — с `<имя>_e2e_test`. Основную локальную базу тесты не трогают.
- **Перед кодом на Next.js** прочитать нужный гайд в `node_modules/next/dist/docs/` (правило `AGENTS.md`). **Перед кодом на Better Auth** — страницы документации из design.md (Context) и код пакета в `node_modules/better-auth`: версия закреплена, поведение проверяем по ней, а не по памяти.
- **`.env` не читаем и не пишем.** Какие строки добавить, говорим владельцу. Если `.env.example` закрыт для агента настройками доступа, владельцу говорим и его строки.
- **Основная локальная база.** Миграцию `0008` (раздаёт данные владельцу) на неё не применять без согласия владельца. Проверки — на временной базе: `createdb` в контейнере, запуск с `DATABASE_URL= POSTGRES_DB=<временная>` из Git Bash. Без `DATABASE_URL=` запуск возьмёт основную базу из `.env`.
- **После каждой группы** — `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, а с группы 5 и `pnpm test:e2e`. Всё зелёное.
