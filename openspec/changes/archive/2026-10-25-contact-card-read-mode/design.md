# Design

## Context

Мотивация — в `proposal.md` (Why), требования — в `specs/contact-card/spec.md` и `specs/contact-list/spec.md`. Макет — копии экранов в `mockups/` рядом с фичой (§10): по ним сверять вид, отступы и расположение. При расхождении с текстами спеки права спека.

Что есть сейчас:

- `src/app/contacts/[id]/page.tsx` — серверный компонент. Внутри `Suspense` грузит контакт (`getContact`) и рендерит шапку (аватар, имя, «Добавлен … · изменён …» через `formatDate` / `formatDateTime`), а под ней `ContactForm mode="edit"`. Ключ формы — `updatedAt`: после сохранения форма пересоздаётся с сохранёнными значениями.
- Главная `src/app/page.tsx` — серверный компонент. Кнопка «Добавить черта» — ссылка на страницу `src/app/contacts/new/page.tsx`: `BackLink`, заголовок «Новый чертила», `ContactForm mode="create"`. После создания форма делает `router.push("/?added=<id>")`, и `ContactDirectory` сбрасывает поиск, прокручивает список к новому контакту и подсвечивает его.
- `src/components/contact-form.tsx` — одна форма для создания и редактирования. Поля обёрнуты в карточку (`FieldGroup` с `rounded-card border bg-card`). Ввод проверяет общая zod-схема — сразу в браузере и потом на сервере. Ctrl+Enter сохраняет из любого поля. В режиме `create` «Отмена» — ссылка на главную, после сохранения — сообщение «Контакт «…» добавлен». В режиме `edit` после сохранения — сообщение «Изменения сохранены», рядом с кнопками — надпись «Есть несохранённые изменения» и `DeleteContactButton`.
- `src/components/delete-contact-button.tsx` — кнопка с текстом «Удалить» и `AlertDialog`: фокус на «Отмена», окно не закрывается, пока идёт удаление, после удаления — сообщение «Контакт «…» удалён» и `router.replace("/")`.
- Серверные действия `createContact`, `updateContact` и `deleteContact` (`src/app/contacts/actions.ts`) уже возвращают `saved` / `invalid` / `not-found` и обновляют страницы через `revalidatePath`. Ответ действия приносит свежие данные, и страница перерисовывается без перезагрузки.
- `next.config.ts`: `cacheComponents: true` — данные из базы читаются внутри `Suspense`. Перед кодом — прочитать нужный гайд в `node_modules/next/dist/docs/` (правило `AGENTS.md`).
- `src/lib/format.ts`: `formatDate` даёт «24 октября 2026 г.», `formatDateTime` — с часами и минутами; обе без часового пояса, то есть в поясе сервера (на проде — UTC). Других мест, где они используются, нет.
- UI: shadcn/ui в стиле `base-nova` поверх `@base-ui/react`. У `Button` есть варианты `outline` (рамка `border-strong`) и `destructive` (красная подложка) — ровно как иконки в макете, и `cta` — как «Сохранить» в окне. `tooltip` и `dialog` в проекте нет, `alert-dialog` есть. Сообщения — `sonner`, `<Toaster position="top-center">` уже стоит в `layout.tsx`.
- Цвета в макете заданы hex-кодами, но это те же значения, что токены в `globals.css` (`--card`, `--muted` — фон окна, `--border`, `--border-strong`, `--muted-foreground`, `--primary`, `--radius-card`). В коде — только токены.

## Goals / Non-Goals

**Goals:**

- Карточка и главная — серверные компоненты. Клиентский код — только кнопки у имени, кнопка «Добавить черта» и окна.
- Одна форма и одна оболочка окна для «Новый чертила» и «Редактировать контакт»: одинаковые поля, подсказки, проверки и поведение без копирования кода.
- Без изменений базы, серверных действий и `package.json`.

**Non-Goals:**

- Поле «Как часто припоминать», строка «мстили …», раздел «Последняя месть» — их добавит `new-features-and-keep-in-touch`.
- Отдельный адрес, по которому сразу открывается окно добавления: старый адрес показывает «не найдено» (решение владельца).
- Подсказки на телефоне по касанию: на сенсорном экране всплывающие подсказки не показываются, там работает доступное имя кнопки.

## Decisions

### 1. Устройство карточки

```
ContactPage (server)
├─ BackLink «Весь список»                          (без изменений)
└─ Suspense → ContactCard (server)
   ├─ header
   │  ├─ ContactAvatar
   │  ├─ h1 name
   │  ├─ ContactCardActions (client)               компьютер: справа от имени; телефон: под строкой дат
   │  │  ├─ Tooltip + Button outline PencilIcon «Редактировать» → EditContactDialog «Редактировать контакт»
   │  │  └─ DeleteContactButton: Tooltip + Button destructive Trash2Icon «Удалить» → AlertDialog «Удалить контакт?»
   │  └─ «Добавлен … · изменён …»
   └─ dl: Откуда знакомы, Телефон, Почта, Заметки
```

- **`ContactCardActions`** — `src/components/contact-card-actions.tsx`, `"use client"`. Получает `contactId`, имя и текущие значения полей для формы. У иконок `aria-label` «Редактировать» / «Удалить», подсказка — shadcn `tooltip`. Нативный `title` не ставим, иначе подсказок будет две.
- **Кнопки рендерятся один раз**, место меняется через CSS. В строке заголовка с переносом (`flex-wrap`): на телефоне имя и строка дат занимают всю ширину, а кнопки уходят в конец (`order-last`); с `sm:` кнопки стоят сразу за именем. Альтернатива — две копии кнопок с `hidden` / `sm:hidden` — отклонена: лишний код, и при двух копиях пришлось бы держать два окна. Порядок для клавиатуры не ломается: из заголовка в фокус попадают только кнопки.
- **Размер иконок:** на телефоне 44×44 (`size="icon-lg"`), с `sm:` — 36×36, как в макете.

### 2. Даты: без «г.» и по московскому времени

- Новый `src/lib/dates.ts`: `APP_TIME_ZONE = "Europe/Moscow"`. Пояс владельца, решение из большой фичи. Туда же большая фича добавит `todayIsoDate()`.
- В `src/lib/format.ts` `formatDate` заменяется на `formatLongDate(date: Date)`. Это `Intl.DateTimeFormat("ru-RU", { day: "numeric", month: "long", year: "numeric", timeZone: APP_TIME_ZONE })`, а строка собирается из частей `day`, `month`, `year` через `formatToParts`, поэтому хвост « г.» в неё не попадает. Имя `formatLongDate` — то же, что в плане большой фичи: там функция научится принимать ещё и строку `date`.
- `formatDateTime` удаляется: время в карточке больше не показываем.
- Порог «изменён» — прежний (`EDIT_NOTICE_THRESHOLD_MS = 60 000`).

Альтернатива — оставить пояс сервера — отклонена: на проде UTC, и всё, что добавлено с 00:00 до 03:00 по Москве, показывалось бы вчерашней датой.

### 3. Поля — список «подпись — значение»

- Разметка `dl` / `dt` / `dd` в карточке `rounded-card border bg-card`, строки разделены линией. С `sm:` — две колонки: подпись слева, ширина колонки как в макете, около 200 px. На телефоне подпись над значением.
- Пустое значение (`value.trim() === ""`) → «не указано» приглушённым курсивом (`text-muted-foreground italic`), как в макете. Ввод и так обрезается по краям zod-схемой, проверка `trim` — на случай старых данных.
- Заметки — `whitespace-pre-wrap break-words`: переносы и пустые строки как в тексте, длинные слова и ссылки переносятся и не вылезают за карточку на телефоне.
- Телефон и почта — обычный текст (proposal, Open Questions 4).

### 4. Окна: общая оболочка и «Редактировать контакт»

- **Общая оболочка окна с формой** — `src/components/contact-form-dialog.tsx`, shadcn `dialog` (Base UI Dialog). Её используют оба окна, чтобы они не разошлись ни видом, ни поведением. Вид — по `mockups/Edit*.dc.html`: заголовок, справа крестик с `aria-label` «Закрыть» (44×44 на телефоне, 36×36 с `sm:`), фон `--muted`, рамка `--border-strong`, скругление `rounded-card`. На компьютере ширина до ~540 px, окно у верхнего края с отступом; на телефоне почти во всю ширину. Если окно выше экрана, оно прокручивается.
- **Свежие значения при каждом открытии.** Содержимое закрытого окна размонтируется, поэтому форма при каждом открытии заново берёт значения из пропсов: в окне редактирования — сохранённые, в окне добавления — пустые. Приём с `key={updatedAt}` больше не нужен.
- **Фокус при открытии** — на поле «Имя». По умолчанию Base UI ставит его на первый фокусируемый элемент, а это был бы крестик.
- **Пока идёт сохранение,** кнопки неактивны, а окно не закрывается ни Esc, ни крестиком — так же, как сейчас подтверждение удаления.
- **Щелчок мимо окна его не закрывает** (proposal, Open Questions 7). Закрывают только «Отмена», Esc и крестик — как в спеке.
- **`EditContactDialog`** — `src/components/edit-contact-dialog.tsx`: оболочка с заголовком «Редактировать контакт» и `ContactForm` в режиме `edit`, открывается карандашом в `ContactCardActions`. `ContactForm` вызывает `updateContact`:
  - `saved` → сообщение «Изменения сохранены», затем `onSaved()` закрывает окно; карточку обновляет `revalidatePath` внутри действия;
  - `invalid` → ошибки у полей, окно открыто;
  - `not-found` → сообщение «Этот контакт не найден. Возможно, его удалили.», окно открыто;
  - сбой сети → прежнее сообщение «Не удалось сохранить…», окно открыто с введёнными данными.

### 5. Окно «Новый чертила» на главной

- **`NewContactDialog`** — `src/components/new-contact-dialog.tsx`, `"use client"`. Встаёт в шапку главной вместо ссылки `Link href="/contacts/new"`: кнопка «Добавить черта» того же вида (`Button size="lg"` с `PlusIcon`) открывает оболочку из §4 с заголовком «Новый чертила» и `ContactForm` в режиме `create`. Остальная главная остаётся серверной.
- **После добавления** форма, как сейчас, показывает «Контакт «…» добавлен» и вызывает `onSaved(id)`. Окно закрывается и делает `router.replace("/?added=<id>")`: дальше работает уже существующая логика `ContactDirectory` — сброс поиска, прокрутка к новому контакту, подсветка. `replace`, а не `push`: мы и так на главной, лишняя запись в истории браузера не нужна.
- **Ошибки** — как в окне редактирования (§4): `invalid` — ошибки у полей, сбой сети — сообщение, окно открыто с введёнными данными.
- **Старый адрес.** Папка `src/app/contacts/new/` удаляется целиком. Адрес `/contacts/new` после этого попадает в маршрут карточки `contacts/[id]`: `parseContactId("new")` даёт `null`, и срабатывает уже существующая страница «Контакт не найден» с кнопкой «К списку контактов». Нового кода не нужно. Альтернативы — перенаправление на главную или главная с открытым окном — владелец отклонил.

### 6. `ContactForm`: одна форма для двух окон

- Оба режима получают колбэки `onSaved` и `onCancel`; «Отмена» в обоих — кнопка, которая вызывает `onCancel`. Куда идти после сохранения, решает хозяин формы: переход на `/?added=<id>` переезжает из формы в `NewContactDialog`.
- Из формы уходят `DeleteContactButton`, надпись «Есть несохранённые изменения» вместе с состоянием `isDirty` и обёртка полей в карточку (`rounded-card border bg-card`): форма теперь живёт только в окнах. Фокус на «Имя» ставит окно, `autoFocus` в форме не нужен.
- Подсказка в пустых «Заметках» — «Что натворил, что обещал, что припомнить» — в обоих режимах. Остальные подсказки в полях — прежние.
- Ctrl+Enter сохраняет и в окнах.
- `BackLink` остаётся только в карточке.

### 7. Удаление

- `DeleteContactButton` вместо кнопки с текстом рендерит иконку: `Button variant="destructive"`, `Trash2Icon`, тот же размер, что у «Редактировать», подсказка «Удалить» и `aria-label`. Содержимое `AlertDialog` — текст, фокус на «Отмена», поведение во время удаления, сообщение и переход на главную — не меняется.
- На одной кнопке встречаются триггер подсказки и триггер `AlertDialog`. Base UI соединяет их через проп `render`. Проверить в браузере, что работают и подсказка, и подтверждение (задача 5.1).

### 8. Что остаётся как есть

- Серверные действия, `generateMetadata` карточки, страница «Контакт не найден», `BackLink`, `ContactDirectory` с подсветкой нового контакта.
- Скелетон загрузки `ContactCardSkeleton` перерисовать под новый вид: аватар, строка имени с двумя квадратами иконок, строка дат, карточка с четырьмя короткими строками.

### 9. Компоненты shadcn

`pnpm dlx shadcn@latest add tooltip dialog`. После добавления проверить `package.json`: новых зависимостей быть не должно. Если CLI потребует новую библиотеку — остановиться и обсудить с владельцем. Если сгенерированному `Tooltip` нужен общий провайдер и сам он его не ставит — обернуть кнопки в `TooltipProvider` внутри `ContactCardActions`, а не во всём `layout.tsx`.

### 10. Макеты рядом с фичой

Папка `mockups/` — копии экранов холста https://claude.ai/artifact/H3fwWd1z31MDDyrMqBkwNW (версия от 24.10.2026):

| Файл | Экран |
| --- | --- |
| `Card.dc.html` | Карточка — просмотр · компьютер |
| `Card-phone.dc.html` | Карточка — просмотр · телефон |
| `Edit.dc.html` | Окно редактирования · компьютер |
| `Edit-phone.dc.html` | Окно редактирования · телефон |

- Копии как в оригинале, убрана только ссылка на служебный скрипт холста (`support.js`): вне холста он не нужен. Файлы открываются в браузере; шрифты грузятся из Google Fonts, поэтому без интернета вид будет другим. Ссылки на экраны, которых в папке нет (главная, «История мести», «Отомстил»), не открываются.
- На экранах есть то, что делает большая фича, а не эта: строка «мстили …», «Как часто припоминать» (в карточке и в окне), раздел «Последняя месть» с «Вся история» и «Отомстил».
- **Окна «Новый чертила» в макете нет.** Оно повторяет `Edit*.dc.html`: заголовок «Новый чертила», поля пустые с прежними серыми подсказками, кнопки «Добавить черта» (вид `cta`) и «Отмена». Экраны страницы «Новый чертила» в холсте (`New`, `New-phone`) к фиче больше не относятся и не копировались.
- Экрана подтверждения удаления контакта в макете нет: окно «Удалить контакт?» остаётся нынешним `AlertDialog` (§7).
- Источник правды по дизайну всего продукта — холст. Если его поменяют, копии сами не обновятся: при изменении экранов этой фичи копии нужно перезаписать.

## Risks / Trade-offs

- [Подсказка и подтверждение на одной кнопке могут конфликтовать] → Проверка в задаче 5.1. Если не работает — обернуть кнопку подсказкой снаружи триггера окна, без новых библиотек.
- [Подсказки Base UI могут не открываться при фокусе с клавиатуры] → Спека требует подсказку и при фокусе — проверить в браузере (задача 3.1); если не открывается, включить это настройкой компонента.
- [Случайное закрытие окна стирает введённое] → Щелчок мимо окна его не закрывает; Esc, крестик и «Отмена» — осознанные действия.
- [По старому адресу `/contacts/new` открывается «Контакт не найден» — текст про контакт, а не про страницу] → Решение владельца — «не найдено»; на странице есть кнопка «К списку контактов». Сам адрес нигде в приложении больше не встречается.
- [Окна нет в макете] → Оно собрано из той же оболочки, что окно редактирования (§4), поэтому выглядит так же.
- [Копии макетов отстают от холста] → В §10 записана версия; копии меняются вместе с требованиями фичи.
- [Москва зашита константой] → Пользователь один и в Москве; пояс в одном месте.

## Migration Plan

1. PR в `main` → CI собирает образ → `deploy.sh`: миграций нет, стартует новое приложение → smoke `/health`.
2. Проверка после выкатки: открыть любой контакт — режим просмотра, даты без времени, иконки с подсказками; «Редактировать» → поменять заметку → «Сохранить» → видно в карточке. На главной «Добавить черта» → окно «Новый чертила» → добавить тестовый контакт → он подсвечен в списке → удалить его корзиной в карточке.
3. Откат — только вручную, по README. База не меняется, поэтому предыдущий образ работает без оговорок.
