# Design

## Context

Мотивация — в `proposal.md` (Why), требования — в `specs/`. Макета нет: блок «Скоро день рождения» повторяет вид блока «Пора мстить» без кнопок, поле в форме — вид соседних полей.

Что есть в коде сейчас:

- Таблица `contacts` (`src/db/schema.ts`): `owner_id`, `name`, `how_we_met`, `phone`, `email`, `notes`, `contact_frequency`, `created_at`, `updated_at`. Последняя миграция — `drizzle/0009_require_owner.sql`; при выкатке миграции применяет разовый контейнер (`scripts/migrate.mjs`).
- Проверка контакта — одна zod-схема `contactInputSchema` (`src/lib/contact-schema.ts`) для формы и серверных действий. Ошибки двух полей групп сводятся в одно поле формы «Группы» (`toFieldErrors`) — так же сведём три части даты в одно поле «Дата рождения».
- `createContact` / `updateContact` (`src/app/contacts/actions.ts`) сохраняют через `insertContact` / `updateContactById` (`src/lib/contacts.ts`); `updateContactById` ставит `updated_at = now()`. Оба действия уже вызывают `revalidatePath("/")` — главная после сохранения свежая.
- Форма `ContactForm` (`src/components/contact-form.tsx`) — одна для окон «Новый чертила» и «Редактировать контакт»; список «Как часто припоминать» — shadcn `select` на `@base-ui/react`. В `src/components/ui/field.tsx` есть `FieldSet` и `FieldLegend`.
- Главная (`src/app/page.tsx`): `DueContacts` в своём `Suspense` со скелетоном, ниже поиск и список. `DueContacts` берёт «сегодня» через `todayIsoDate()` после `await io()` и группу через `resolveGroupFilter`.
- «Пора мстить» считается одним SQL-запросом в `src/lib/keep-in-touch.ts`: фильтр по владельцу и группе, сортировка имён в коллации `"ru-RU-x-icu"`, как у общего списка.
- `src/lib/dates.ts`: `todayIsoDate(now?)` — «сегодня» по Москве строкой `YYYY-MM-DD`. `src/lib/format.ts`: `pluralize`.
- Тесты: Vitest на тестовой базе (`src/test/factories.ts`, `resetDatabase`), тесты миграций в `src/db/migrations.test.ts`, Playwright на настоящей базе (`e2e/database.ts` — `addContact`, `addGroup`, `addUser`; `e2e/contact-card.ts` — `cardField`).
- `next.config.ts`: `cacheComponents: true`. Перед кодом на Next.js — гайды в `node_modules/next/dist/docs/` (правило `AGENTS.md`).

## Goals / Non-Goals

**Goals:**

- Год можно не указывать, и это видно в данных явно, без выдуманного года-заглушки.
- Кто попадает в блок и в каком порядке — один SQL-запрос, как у «Пора мстить».
- Правила даты — одна схема для формы и сервера.
- Без новых библиотек.

**Non-Goals:**

- Возраст, уведомления, поиск и сортировка по дате рождения.
- Индекс под запрос дней рождения: у пользователя около тысячи контактов, запрос и так читает только его строки по `contacts_owner_id_idx`.

## Decisions

### 1. Модель данных — три колонки

```
contacts
  …            (как сейчас)
  birth_day    smallint NULL   ← новое, 1–31
  birth_month  smallint NULL   ← новое, 1–12
  birth_year   smallint NULL   ← новое, NULL = год не указан

check contacts_birthday_check:
  (birth_day IS NULL AND birth_month IS NULL AND birth_year IS NULL)
  OR (birth_day IS NOT NULL AND birth_month IS NOT NULL
      AND birth_month BETWEEN 1 AND 12
      AND birth_day BETWEEN 1 AND CASE birth_month WHEN 2 THEN 29
                                    WHEN 4 THEN 30 WHEN 6 THEN 30 WHEN 9 THEN 30 WHEN 11 THEN 30
                                    ELSE 31 END)
```

- **Почему три колонки.** Альтернативы: колонка `date` с годом-заглушкой для «без года» (отклонено: заглушка проникает в отчёты и возраст, а 29 февраля требует високосной заглушки) и `date` + флаг «год известен» (отклонено: два источника правды). Три числа прямо отражают то, что вводит владелец.
- **Проверка в базе** — страховка от прямой записи мимо приложения: день и месяц вместе, день есть в месяце. Тонкие правила (29 февраля в невисокосный год, год не раньше 1900, не позже сегодня) — только в схеме (§3): «сегодня» база не знает по Москве.
- В Drizzle — `smallint("birth_day")` и т. д. и `check(...)` в третьем аргументе `pgTable`. Миграция `pnpm db:generate --name add_birthday` → `drizzle/0010_add_birthday.sql`: три `ADD COLUMN` с NULL и `ADD CONSTRAINT`. Существующие строки не меняются: у всех «не указано».

### 2. Общий модуль `src/lib/birthday.ts`

Работает и в браузере, и на сервере (без `server-only`):

- `BIRTH_MONTHS` — названия месяцев в родительном падеже: «января» … «декабря». Один список для формы, карточки и блока.
- `type Birthday = { day: number; month: number; year: number | null }`.
- `formatBirthday(birthday)` → «17 ноября 1990» или «17 ноября» (карточка).
- `formatBirthdayLabel(nextOn, today)` → «сегодня · 14 ноября», «завтра · 15 ноября», «через 3 дня · 17 ноября». Обе даты — `YYYY-MM-DD`; разница в днях считается в UTC, как `previousIsoDate` в `format.ts`, поэтому пояс не сдвигает день. «дня / дней» — через `pluralize`.

### 3. Проверка ввода

В `contactInputSchema` новое поле `birthday` — объект из трёх строк, как их отдаёт форма: `{ day: "17", month: "11", year: "" }`. Месяц из списка — `"1"`…`"12"` или `""`. Поле необязательное: запрос без него (старая открытая вкладка) читается как пустая дата — так же, как сейчас `groupIds`.

Правила по порядку, первая сработавшая ошибка — единственная:

1. Всё пусто → `null` (даты нет).
2. День или месяц пуст → «Укажите день и месяц».
3. День — не 1–2 цифры, месяц — не 1–12, такого дня нет в месяце (29 февраля без года можно) → «Такой даты нет».
4. Год не пуст и не четыре цифры или меньше 1900 → «Год — четыре цифры, не раньше 1900».
5. 29 февраля и год невисокосный → «Такой даты нет».
6. С годом дата позже `todayIsoDate()` → «Дата рождения не может быть позже сегодняшней». «Сегодня» считается при каждой проверке, как у записей о мести.

Выход схемы — `Birthday | null`. Ошибка пишется в путь `birthday`; `toFieldErrors` отдаёт её как поле `birthday`. `ContactFormInitialValues.birthday` — `Birthday | null`.

`insertContact` / `updateContactById` раскладывают `birthday` в три колонки (`null` → три `NULL`). Дата «изменён» двигается на любом сохранении, как сейчас.

### 4. Форма

`FieldSet` с `FieldLegend` «Дата рождения» между «Почтой» и «Как часто припоминать». В одну строку три части:

- **День** — `Input`, `inputMode="numeric"`, `maxLength={2}`, подсказка «День», узкое.
- **Месяц** — shadcn `Select`, как «Как часто припоминать»: первый пункт `null` «Не указан» (стереть месяц), дальше «января» … «декабря». Пустой показывает серую подсказку «Месяц» — через функцию-потомка `SelectValue`; как именно — сверить с кодом `@base-ui/react` в `node_modules`.
- **Год** — `Input`, `inputMode="numeric"`, `maxLength={4}`, подсказка «Год».

У частей доступные имена «День», «Месяц», «Год»; группа читается как «Дата рождения». Ошибка — одна `FieldError` под строкой; при ошибке фокус на «День». Высота частей 44 px, как у соседних полей; на телефоне строка помещается в 375 px: день и год узкие, месяц занимает остаток.

Нативное поле `type="date"` отклонено: оно требует год.

### 5. Карточка

Строка `TextField` «Дата рождения» со значением `formatBirthday(...)` или пустым (→ «не указано») после «Почты», перед «Как часто припоминать». Скелетон получает ещё одну строку. `ContactCardActions` передаёт окну редактирования `birthday`.

### 6. Кто попадает в блок — один SQL-запрос

`src/lib/birthdays.ts` (`server-only`), `listUpcomingBirthdays(ownerId, today, groupId)` → `{ id, name, nextOn }[]`:

```sql
select id, name, next_on::text
from (
  select c.id, c.name,
    (select min(on_date) from (
       select make_date(y, c.birth_month, 1) + (c.birth_day - 1) as on_date
       from (values (:year), (:year + 1)) years(y)
     ) candidates
     where extract(month from on_date) = c.birth_month
       and on_date >= :today::date) as next_on
  from contacts c
  where c.owner_id = :ownerId and c.birth_month is not null <фильтр группы>
) upcoming
where next_on <= :today::date + 7
order by next_on, name collate "ru-RU-x-icu", id
```

- День рождения в году `y` — первое число месяца плюс (день − 1). Для 29 февраля в невисокосный год получается 1 марта: месяц не совпал — этот год пропускаем, как требует спека. `make_date(y, 2, 29)` напрямую не годится: в невисокосный год он падает с ошибкой. Остальные даты существуют в любом году (день проверен схемой и `check`).
- Берутся этот и следующий год; ближайший не раньше сегодня — и есть следующий день рождения. Так работает переход через Новый год. Если оба года пропущены (29 февраля, а ни этот, ни следующий год не високосный), `next_on` пустой, и `next_on <= …` отбрасывает строку.
- `today` и `year` приходят параметрами из `todayIsoDate()`, а не через `current_date` Postgres (у того пояс сессии), как в `listDueContacts`.
- Фильтр группы — тот же `exists` по `contact_groups`, что в `listDueContacts`. `id` — последний разбор ничьей.
- Альтернатива — считать в TypeScript по всем датам владельца — отклонена: порядок имён должен совпадать с ICU-коллацией общего списка, а запрос «Пора мстить» уже живёт по этому образцу.

### 7. Главная

Серверный компонент `UpcomingBirthdays` (`src/components/upcoming-birthdays.tsx`) читает список и готовит тексты подписей, клиентский `UpcomingBirthdaysList` (`src/components/upcoming-birthdays-list.tsx`) показывает первых пятерых и раскрывает остальных — так же, как `DueContacts` и `DueContactsList`.

- **Место.** В тот же `Suspense`, что и `DueContacts`, внутри обёртки `flex flex-col gap-3` с прежним отступом до поиска: сначала `UpcomingBirthdays`, потом `DueContacts`. Оба блока появляются разом вместо скелетона «Пора мстить» — страница не прыгает дважды. Отдельный `Suspense` отклонён: блок может оказаться пустым, а скелетон, который потом исчезает, хуже, чем его отсутствие. Скелетон остаётся прежним — одна рамка «Пора мстить».
- **Пусто** → `UpcomingBirthdays` возвращает `null`: ни заголовка, ни отступа (у `flex gap` нет промежутка рядом с несуществующим элементом), под строкой групп сразу «Пора мстить».
- **Первые пять — общий кусок с «Пора мстить».** Из `DueContactsList` выносим в `src/components/show-more.tsx`: хук `useCollapsedList(items)` — `expanded`, видимые строки (`items.slice(0, 5)` до раскрытия), число скрытых и перенос фокуса на шестую ссылку после раскрытия — и строку `ShowMoreItem` — кнопку «+ещё N людишек» со склонением (`pluralize`), `aria-expanded="false"` и стрелкой, тем же видом. `DueContactsList` переходит на них без изменения поведения; его тесты в `e2e/keep-in-touch.spec.ts` не меняем — они и сторожат вынос. Альтернатива — скопировать код в новый блок — отклонена: два экземпляра одного поведения (текст, склонение, фокус) со временем разойдутся.
- **Смена группы сворачивает список:** `UpcomingBirthdays` отдаёт `UpcomingBirthdaysList` с `key` по группе, как `DueContacts`, — новая группа начинает новый список с первыми пятью.
- **Вид** — как `DueContactsList`: `section` с `aria-labelledby`, `h2` «Скоро день рождения» тем же шрифтом и размером, строки через линию; имя — та же подчёркнутая ссылка на `/contacts/<id>`; под ним мелким серым подпись, где «когда» («сегодня», «через 3 дня») — цветом акцента `text-primary font-medium`, как срок в «Пора мстить», а « · 17 ноября» — серым. Кнопок в строках нет.
- «Сегодня» — после `await io()`, как в `DueContacts`; группа — `resolveGroupFilter(params.group, …)`.

### 8. Тестовые данные

`scripts/seed-data.ts`: отдельная последовательность случайных чисел (`seed + 3`), чтобы имена, заметки, частота и группы остались прежними. Примерно 30% контактов получают день рождения — случайный день високосного года (29 февраля тоже бывает), из них примерно четверть без года, остальным год 1960–2005. Из тысячи контактов в окно 8 дней в среднем попадает 6–7 человек.

### 9. Тесты

Каждый сценарий спеки — свой тест:

- **Vitest без базы** — `src/lib/birthday.test.ts` (`formatBirthday`, `formatBirthdayLabel`) и `src/lib/contact-schema.test.ts` (сценарии «Проверка даты рождения»; «сегодня» подменяется `vi.useFakeTimers` / `vi.setSystemTime`).
- **Vitest на тестовой базе** — `src/lib/birthdays.test.ts`: сценарии «Кто попадает», «Порядок», группа, «только свои», с фиксированным `today` (14.11.2026, 28.12.2026, 25.02.2027, 25.02.2028); `src/db/migrations.test.ts` — «Существующие контакты»; `src/app/contacts/actions.test.ts` — «Запрос не из формы».
- **Playwright** — `e2e/birthdays.spec.ts`: окна, карточка, блок на главной — место над «Пора мстить», первые пять и «+ещё N людишек», группы. Даты — от настоящего «сегодня» по Москве (`todayIsoDate()`), как в `e2e/keep-in-touch.spec.ts`. `e2e/database.ts` `addContact` получает `birthday`.

## Risks / Trade-offs

- [Год-«19а0» на телефоне не набрать, а через вставку — можно] → Схема проверяет четыре цифры; `inputMode="numeric"` лишь подсказывает клавиатуру.
- [Вынос строки «+ещё …» из `DueContactsList` может сломать «Пора мстить»] → Выносим отдельной задачей до кода нового блока; тесты «Пора мстить» не правим, они должны остаться зелёными.
- [Блок дней рождения появляется над «Пора мстить» и сдвигает его вниз после загрузки] → Сдвиг один — вместе с заменой скелетона, как и сейчас.
- [Человек с днём рождения 29 февраля три года из четырёх не попадает в блок] → Так решил владелец; дата в карточке видна всегда.
- [Владелец на телефоне в другом часовом поясе увидит «сегодня» по Москве] → Как и «Пора мстить»: пользователь в Москве, пояс — одна константа.
- [Подпись функции-потомка `SelectValue` у Base UI может отличаться] → Сверить с кодом пакета до кода формы; новых библиотек не нужно.

## Migration Plan

1. PR в `main` → CI собирает образ → тест-стенд: миграция `0010` → новый образ → smoke `/health`. На прод — вручную, через Deploy prod.
2. Проверка после выкатки: у контактов «Дата рождения» — «не указано», блока «Скоро день рождения» нет. Указать контакту дату рождения на завтра — на главной появляется блок с подписью «завтра · …».
3. Откат — только вручную, по README. Миграция только добавляет колонки с NULL и проверку, которой существующие строки удовлетворяют, поэтому прошлый образ работает с новой базой и просто не видит дату рождения.
