# Tasks

Автотестов в проекте нет, а тестовый раннер — новая библиотека (обсуждать с владельцем). Поэтому проверки ниже — `pnpm typecheck`, `pnpm lint`, `pnpm build`, SQL-запросы к локальной базе, разовые проверки через `pnpm tsx -e "…"` и ручные проверки в браузере на `pnpm dev`. Перед кодом на Next.js — прочитать нужный гайд в `node_modules/next/dist/docs/` (правило `AGENTS.md`). Временные базы для проверок создавать рядом с основной в локальном контейнере Postgres (`createdb` / `dropdb`); основную локальную базу не удалять.

## Workflow follow-up

- «Коммить и пуш» — по команде владельца: коммит в ветку `interaction-history`, push, PR в `main`, ссылка на PR.
- После merge — выкатка через CI; проверить smoke `/health` и перенос записей на проде по design.md (Migration Plan, п. 2). Красный smoke — сообщить владельцу, ничего не откатывать.
- Архивировать изменение (`/opsx:archive`) после выкатки и проверки.
- Затем — реализовать `new-features-and-keep-in-touch`: она уже сокращена до частоты и «Пора мстить» и опирается на эту фичу.
