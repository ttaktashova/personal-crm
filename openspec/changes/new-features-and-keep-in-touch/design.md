# Design

## Context

Мотивация — в `proposal.md` (Why), требования — в `specs/`. Макет всех экранов для компьютера и телефона: https://claude.ai/artifact/H3fwWd1z31MDDyrMqBkwNW — по нему сверять вид, отступы и расположение; при расхождении с текстами спек правы спеки.

Что есть сейчас:

- Одна таблица `contacts` (`src/db/schema.ts`): `name`, `how_we_met`, `phone`, `email`, `notes`, `created_at`, `updated_at`. Миграции Drizzle лежат в `drizzle/`; при выкатке их применяет разовый контейнер (`scripts/migrate.mjs`). Drizzle выполняет все новые миграции в одной транзакции: упала любая — не применяется ни одна, и новый образ не стартует.
- Карточка `src/app/contacts/[id]/page.tsx` — серверный компонент, который сразу рендерит `ContactForm` в режиме `edit`. Кнопка удаления (`DeleteContactButton`) живёт внутри формы.
- Серверные действия `src/app/contacts/actions.ts` проверяют ввод общей zod-схемой (`src/lib/contact-schema.ts`) и после записи вызывают `revalidatePath` — ответ действия приносит свежие данные страницы, и карточка перерисовывается без перезагрузки. Этот приём сохраняем для всех новых действий.
- `next.config.ts`: `cacheComponents: true`. Данные из базы читаются внутри `Suspense`; текущее время (`new Date()`) в серверном компоненте можно брать только после обращения к динамическим данным, иначе сборка падает с ошибкой prerender. Перед кодом — читать гайды в `node_modules/next/dist/docs/` (правило `AGENTS.md`).
- UI: shadcn/ui в стиле `base-nova` поверх `@base-ui/react`. Сейчас добавлены `alert-dialog`, `button`, `field`, `input`, `textarea` и др.; `dialog`, `select`, `tooltip` нет.
- Даты сейчас форматируются без часового пояса (`src/lib/format.ts`), то есть в поясе сервера — на проде это UTC.
- Тестовые заметки из `pnpm db:seed` устроены как абзацы «ДД.ММ.ГГГГ — текст», разделённые пустой строкой. На проде, вероятно, такие же данные плюс реальные контакты.
- Репозиторий публичный: в миграциях и коде не должно быть данных конкретных контактов, только общие правила.

## Goals / Non-Goals

**Goals:**

- История мести — отдельная таблица, а не разбор текста заметок при каждом показе.
- Одна точка правды для «сегодня» и для правил срока, одинаковая на сервере и в браузере.
- Разовый перенос из заметок, который идёт в существующем конвейере миграций и не требует новых шагов выкатки.
- Без новых npm-библиотек.

**Non-Goals:**

- Уведомления и напоминания вне приложения (в продуктовой идее — «Не делать»).
- Показ последней мести или частоты в общем списке контактов, фильтры по ним.
- Переименование кода под новые надписи: в «Черном списке» меняются только тексты интерфейса, а имена в коде (`interactions`, `contact_frequency`, `keep-in-touch`, `markContacted`, `stopReminders`) остаются нейтральными английскими.
- Постраничная загрузка истории мести: записей у одного человека — десятки, грузим все.
- Настройка часового пояса: пользователь один, пояс зашит константой.

## Decisions

### 1. Модель данных

```
contacts                                   interactions
  id               integer PK                id           integer PK (identity)
  name …           (как сейчас)              contact_id   integer NOT NULL → contacts.id ON DELETE CASCADE
  notes            text                      occurred_on  date NOT NULL
  contact_frequency  contact_frequency NULL  summary      text NOT NULL
  created_at, updated_at                     created_at   timestamptz NOT NULL DEFAULT now()

enum contact_frequency: 'week' | 'month' | 'quarter' | 'year'     (NULL = «Не задано»)
index interactions (contact_id, occurred_on DESC, id DESC)
```

- **`occurred_on` — тип `date`**, в Drizzle `date(..., { mode: "string" })`: значение приходит строкой `"2026-10-24"` и нигде не превращается в `Date`, поэтому не съезжает на день из-за часовых поясов.
- **`summary` хранит итоговый текст**, включая «Отомстил» по умолчанию: подстановка делается при сохранении, а не при показе. Так в базе ровно то, что видно на экране.
- **Последняя запись берётся из `interactions`** (`max(occurred_on)`, при равенстве — больший `id`), а не хранится в `contacts`. Альтернатива — колонка `last_interaction_on` в `contacts` — отклонена: её надо пересчитывать при каждом добавлении и удалении записи, а при ~1000 контактов выборка по индексу дешёвая.
- **Частота — enum, NULL = не задано.** Альтернативы: число дней (отклонено: месяц и год не равны фиксированному числу дней, а спека требует календарных), хранимая «дата следующей мести» (отклонено: та же проблема пересчёта).
- **`ON DELETE CASCADE`** — история удаляется вместе с контактом без изменений в `deleteContact`.
- Добавление, изменение и удаление записей о мести не трогают `contacts.updated_at`; смена частоты — трогает (она поле карточки).
- **`updated_at` у `interactions` нет:** время правки записи нигде не показывается. Изменённая запись сохраняет `id`, поэтому среди записей с одной датой остаётся на прежнем месте («добавленная позже» — по `id`).

### 2. «Сегодня» и часовой пояс

`src/lib/dates.ts`: константа `APP_TIME_ZONE = "Europe/Moscow"` и `todayIsoDate()` — дата `"YYYY-MM-DD"` в этом поясе через `Intl.DateTimeFormat` с `timeZone`. Функция работает и на сервере, и в браузере, поэтому:

- дата по умолчанию в окне «Отомстил» — московское сегодня, даже если в браузере другой пояс;
- сервер проверяет «не позже сегодня» по той же функции;
- кнопка «Отомстил» на главной берёт дату на сервере, а не из браузера;
- запрос «пора мстить» получает `today` параметром из TS, а не через `current_date` Postgres (у того пояс сессии).

Форматтеры в `src/lib/format.ts` тоже получают `timeZone: APP_TIME_ZONE`, чтобы «Добавлен / изменён» совпадали с московской датой.

Альтернатива — пояс браузера через cookie — отклонена: лишняя сложность для одного пользователя.

### 3. Форматы дат

- `formatLongDate` → «24 октября 2026». `Intl` для `ru-RU` даёт «24 октября 2026 г.», поэтому берём `formatToParts` и выкидываем хвост « г.». Принимает строку `date` или `Date` (для `created_at` / `updated_at`, переводится в московскую дату).
- `formatShortDate("2026-10-24")` → «24.10.2026» — собирается из частей строки, без `Date`.
- `formatDueLabel(dueOn, today)` → «пора сегодня» / «пора со вчера» / «пора с 01.10.2026» для строки блока «Пора мстить». «Вчера» — это `today` минус один календарный день; обе даты — строки `YYYY-MM-DD` в московском поясе, поэтому сравнение не зависит от пояса сервера.
- Старый `formatDateTime` больше не нужен (время в карточке не показываем) — удалить.

### 4. Расчёт «пора мстить» — один SQL-запрос

`src/lib/keep-in-touch.ts`, `listDueContacts(today)`:

```sql
select c.id, c.name, c.contact_frequency, last.occurred_on as last_on,
       (last.occurred_on + case c.contact_frequency
          when 'week' then interval '7 days'  when 'month' then interval '1 month'
          when 'quarter' then interval '3 months' when 'year' then interval '1 year' end)::date as due_on
from contacts c
left join lateral (select max(occurred_on) as occurred_on
                   from interactions i where i.contact_id = c.id) last on true
where c.contact_frequency is not null
  and (last.occurred_on is null or <due_on> <= :today)
order by (last.occurred_on is null) desc, due_on asc, c.name collate "ru-RU-x-icu", c.id
```

Порядок по спеке: сначала те, кому ещё не мстили (`due_on` у них пустой), потом по `due_on` от раннего к позднему, а при равном сроке — имя по алфавиту (от А к Я) в той же ICU-коллации, что и общий список; `id` — последний разбор ничьей, чтобы порядок не прыгал. `due_on` возвращается в приложение и превращается в подпись через `formatDueLabel` (§3).

`date + interval '1 month'` в Postgres сам обрабатывает конец месяца (31.01 → 28.02), это и требует спека. Альтернатива — считать в JS по всем контактам — отклонена: пришлось бы тянуть все контакты с последними датами и самим реализовывать календарную арифметику.

Подписи частот («Раз в неделю» …) и список значений — в `src/lib/contact-frequency.ts`, общий для формы, карточки и главной.

### 5. Проверка ввода

- `contactInputSchema` получает `contactFrequency`: одно из значений enum или `null`. Пункт «Не задано» в форме отправляет пустую строку → схема превращает её в `null`.
- Новый `src/lib/interaction-schema.ts` по образцу `contact-schema.ts`: `occurredOn` — строка `YYYY-MM-DD`, реальная дата, не позже `todayIsoDate()`; `summary` — `trim`, до 2000 символов, пустая → «Отомстил» (константа `DEFAULT_INTERACTION_SUMMARY`). Одна схема для добавления и изменения записи, общая для формы (мгновенные ошибки) и сервера (источник правды). Сообщения об ошибках — на русском, как в спеке.

### 6. Серверные действия

Результаты в том же стиле, что сейчас (`{ status: "saved" | "invalid" | "not-found" | … }`), после записи — `revalidatePath("/")` и `revalidatePath("/contacts/<id>")`.

- `src/app/contacts/actions.ts`: `createContact` / `updateContact` сохраняют `contactFrequency`; новое `stopReminders(contactId)` — `contact_frequency = null`, `updated_at = now()`.
- `src/app/contacts/interaction-actions.ts`: `addInteraction(contactId, input)`, `updateInteraction(interactionId, input)` и `deleteInteraction(interactionId)` (оба берут `contact_id` из `returning`, чтобы знать, какую карточку обновить; запись не найдена → `not-found`), `markContacted(contactId)` — запись на сегодня с «Отомстил».

### 7. Карточка

Страница грузит контакт и все его записи (новые сверху) параллельно и рендерит режим просмотра на сервере. Интерактивные части — небольшие клиентские компоненты:

```
ContactPage (server)
├─ BackLink «Весь список»
├─ header: avatar, h1 name, ContactCardActions (client)
│    ├─ Tooltip + icon Button «Редактировать» → EditContactDialog «Редактировать контакт» (Dialog + ContactForm mode="edit")
│    └─ DeleteContactButton (вариант-иконка, новый текст подтверждения)
├─ «мстили 24 октября 2026» / «Пока не мстили»
├─ «Добавлен … · изменён …»
├─ поля: Откуда знакомы, Телефон, Почта, Как часто припоминать
├─ InteractionSection (client)
│    ├─ последняя запись / «Пока не мстили»
│    ├─ «Вся история» → InteractionHistoryDialog — одно окно с видами:
│    │                    list | add (InteractionForm) | edit (InteractionForm) | confirm-delete
│    └─ «Отомстил» → InteractionDialog (Dialog + InteractionForm mode="add")
└─ Заметки (whitespace-pre-wrap)
```

- **Окна** — shadcn `dialog` (Base UI Dialog). Содержимое закрытого окна размонтируется, поэтому форма при каждом открытии заново берёт сохранённые значения — так выполняется требование «после отмены видны сохранённые данные». **Окон поверх окон нет** (решение владельца по макету): окно истории не открывает вложенных окон, а переключает своё содержимое.
- **`InteractionForm`** — поля и кнопки записи: «Дата» (по умолчанию московское сегодня) и «Как отомстил» с серой подсказкой «Отомстил»; «Сохранить» / «Отмена». Режим `add` (заголовок «Отомстил») вызывает `addInteraction`, `edit` (заголовок «Изменить запись», поля заполнены) — `updateInteraction`. Форма не знает, где стоит: колбэки `onSaved` / `onCancel` решает её хозяин. Если `updateInteraction` вернул `not-found`, форма показывает `toast.error` и вызывает `router.refresh()`: сервер не знает, к какому контакту относилась удалённая запись, поэтому обновить карточку через `revalidatePath` не может.
- **`InteractionDialog`** — окно «Отомстил» из раздела «Последняя месть» карточки: `Dialog` + `InteractionForm mode="add"`, после сохранения или отмены закрывается.
- **`InteractionHistoryDialog`** — окно «История мести». Вид хранится в состоянии компонента: `list` → «Отомстил» даёт `add`, карандаш — `edit` с записью, корзина — `confirm-delete` с записью; «Сохранить», «Удалить» и «Отмена» возвращают к `list`. В форме слева от заголовка кнопка-стрелка «Назад к истории» (`aria-label`), справа крестик. Подтверждение показывает саму запись, текст «Запись от ДД.ММ.ГГГГ удалится насовсем.», кнопки «Отмена» (на ней фокус) и «Удалить». При смене вида фокус переходит на заголовок нового вида, чтобы экранный диктор объявил его. Крестик и Esc закрывают окно целиком. Отдельный `DeleteInteractionButton` с `AlertDialog` не нужен.
- **`ContactForm`** остаётся одной формой для страницы создания и окна редактирования: получает поле частоты (shadcn `select` с `name`, значение попадает в `FormData`), колбэки `onSaved` / `onCancel` для окна; кнопка удаления и подсказка «Есть несохранённые изменения» из формы уходят. Подсказка в пустых «Заметках» — «Что натворил, что обещал, что припомнить», кнопка сохранения в режиме создания — «Добавить черта». В окне «Сохранить» закрывает его только после ответа сервера, ошибки показываются в окне.
- **Иконки** — `lucide-react` (уже есть): `PencilIcon`, `Trash2Icon`, у записи — те же `PencilIcon` и `Trash2Icon`, в форме окна истории — `ArrowLeftIcon`; подсказки — shadcn `tooltip`, у кнопок `aria-label`. На телефоне иконки-кнопки 44×44, на компьютере 36×36.
- Скелетон загрузки карточки обновить под новый вид.

### 8. Главная: блок «Пора мстить»

Отдельный серверный компонент `DueContacts` в своём `Suspense` над списком: блок и список грузятся независимо. Сервер отдаёт весь список; внутри — клиентский `DueContactsList`: имя-ссылка, «частота · подпись срока» (`formatDueLabel` или «ещё не мстили») и две кнопки.

- **Первые пять.** Клиент хранит `expanded` (по умолчанию `false`) и показывает `expanded ? all : all.slice(0, 5)`. Если людей больше пяти и список свёрнут — последней строкой кнопка «+ещё N людишек» (`pluralize(n, ["людишка", "людишки", "людишек"])` из `src/lib/format.ts`, `aria-expanded="false"`); нажатие ставит `expanded = true`, строка исчезает. «Свернуть» нет. После «Отомстил» / «Простить» сервер присылает список без этого человека, и в свёрнутом виде на его место поднимается шестой.
- **Кнопки.** Одна кнопка на действие, вид зависит от ширины: от 640 px (`sm:`) — текст «Отомстил» / «Простить» (`Button size="sm"`), уже — иконка 44×44 (`CheckIcon` на красном фоне и `BellOffIcon` с рамкой из `lucide-react`) с подсказкой shadcn `tooltip`. Текст и иконка лежат в одной кнопке, лишнее скрыто через `hidden sm:inline` / `sm:hidden`. `aria-label` — «Отомстил: <имя>» / «Простить: <имя>» всегда. На телефоне иконки стоят справа от имени, в одну строку.
- Каждая кнопка вызывает своё серверное действие в `useTransition`, на время выполнения кнопки строки неактивны; ответ действия приносит свежий список, и строка пропадает. Ошибка — `toast.error`, как в существующих компонентах.

Список пустой → вместо блока `DueContacts` рисует компактную карточку «Пока некому мстить»: слева картинка `CatSad` (`src/components/cat-sad.tsx`) около 56–64 px, справа надпись в одну строку. Картинка — inline SVG в стиле `CatConfused`: те же токены `--cat`, `--cat-eye`, `--cat-pink` и `aria-hidden`, потому что смысл передаёт надпись. Карточка показывается и тогда, когда контактов нет совсем.

`today` берётся после чтения `searchParams` / данных, чтобы не нарушить правило `cacheComponents` про текущее время.

### 9. Перенос из заметок — SQL-миграция с PL/pgSQL

Две миграции:

1. `0001_…` — генерирует `pnpm db:generate` из схемы: enum, колонка, таблица, индекс.
2. `0002_copy_interactions_from_notes.sql` — пишется руками (`drizzle-kit generate --custom`), один блок `DO $$ … $$`:
   - `today := (now() at time zone 'Europe/Moscow')::date`;
   - для каждого контакта с непустыми `notes` — разбить на строки (`\r?\n`); строка, совпавшая с `^\s*(\d{1,2})\.(\d{1,2})\.(\d{4})\s*[—–:-]?\s*(.*)$`, начинает запись, если `make_date(...)` даёт реальную дату (ошибку ловит `BEGIN … EXCEPTION`) и она не позже `today`; иначе строка — обычный текст;
   - строки без даты после датированной добавляются к её тексту; итоговый текст `btrim`, пустой → «Отомстил»;
   - текст до первой датированной строки делится на абзацы по пустым строкам; абзацы, где `lower(p collate "ru-RU-x-icu")` содержит одно из слов спеки, склеиваются через пустую строку в одну запись с датой `(updated_at at time zone 'Europe/Moscow')::date`;
   - записи вставляются в порядке строк заметок, поэтому при одинаковой дате «добавленной позже» считается та, что ниже в заметках.
   - `contacts` миграция не изменяет.

Почему SQL, а не TS-скрипт: миграция идёт в существующем шаге выкатки, ровно один раз (её учитывает журнал Drizzle) и в той же транзакции, что и создание таблицы. TS-скрипту понадобился бы новый шаг в `deploy.sh` и свой признак «уже выполнено».

Почему `collate "ru-RU-x-icu"` для `lower`: регистр кириллицы в `lower()` зависит от локали базы, а ICU-коллация уже используется приложением для сортировки и даёт правильный результат независимо от локали.

### 10. Тестовые данные

`scripts/seed-data.ts` вместе с заметкой «ДД.ММ.ГГГГ — текст» создаёт такую же запись о мести, а примерно четверти контактов задаёт случайную частоту. `scripts/seed.ts` вставляет контакты, затем их записи. Так на свежей базе (где перенос из заметок уже отработал на пустой таблице) есть что проверить в «Пора мстить». Существующую локальную базу seed по-прежнему не трогает.

### 11. Компоненты shadcn

`pnpm dlx shadcn@latest add dialog select tooltip`. После добавления проверить `package.json`: новых зависимостей быть не должно (всё строится на `@base-ui/react`). Если CLI потребует новую библиотеку — остановиться и обсудить с владельцем. Поле даты — `Input type="date"`: календарь shadcn тянет `react-day-picker`, это новая зависимость.

## Risks / Trade-offs

- [Правило «дата в начале строки = запись» переносит и посторонние сведения, например «15.10.2026 — Дети: …»] → Так решил владелец; заметки не меняются, лишнюю запись можно изменить или удалить в окне истории.
- [Слова-признаки для текста без даты пропустят нужное или поймают лишнее] → Перенос только копирует; список слов зафиксирован в спеке; недостающую запись владелец добавит кнопкой «Отомстил».
- [Ошибка в PL/pgSQL роняет выкатку] → Миграция в одной транзакции со схемой: упала — база не меняется, работает старая версия. Перед PR прогнать миграции на локальной базе с 1000 тестовыми контактами и сверить счётчики (число датированных строк в заметках = число записей с этих строк).
- [Пользователь в другом часовом поясе увидит «сегодня» по Москве] → Пользователь один и в Москве; пояс — одна константа.
- [Блок «Пора мстить» станет длинным, если задать частоту многим контактам без истории] → Видно первых пятерых, остальные — по «+ещё N людишек».
- [Смена видов внутри окна истории: можно потеряться, где находишься] → У каждого вида свой заголовок, фокус переходит на него; стрелка «назад» и «Отмена» всегда возвращают к списку.
- [Иконки на телефоне менее очевидны, чем текст] → Выбраны привычные символы (галочка — сделано, перечёркнутый колокольчик — не напоминать), у кнопок подсказка и `aria-label` с именем; на компьютере остаётся текст.

## Migration Plan

1. PR в `main` → CI собирает образ → `deploy.sh` применяет `0001` и `0002` в одной транзакции → стартует новое приложение → smoke `/health`.
2. Проверка после выкатки: открыть контакт с датированными заметками — в «Последняя месть» последняя запись, в «Вся история» все датированные абзацы; заметки прежние.
3. Откат — только вручную, по README. Миграции только добавляют (новая таблица, новая колонка с NULL), поэтому предыдущий образ работает с новой базой и просто не видит историю и частоту. Повторная выкатка новой версии перенос не повторит — миграция уже записана в журнале.
4. Если перенос дал не тот результат — записи удаляются в интерфейсе или отдельной миграцией по согласованию; автоматического отката нет.
