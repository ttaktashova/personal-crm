# Черный список

Личная CRM, но не телефонный справочник, а блокнот тех, кому хочется отомстить: кто это, откуда знакомы, телефон, почта и заметки о том, что натворил и чем всё закончилось. Чтобы никого не забыть и вовремя припомнить.

Идея и критерии успеха — в [`specs/01-продуктовая-идея.md`](specs/01-продуктовая-идея.md).

## Что нужно установить

- [Node.js](https://nodejs.org/) 24
- [pnpm](https://pnpm.io/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает база данных PostgreSQL

## Первый запуск

1. Скопируйте `.env.example` в `.env` и заполните значения: имя пользователя, пароль и название базы (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`). Вместо них можно указать одну строку подключения `DATABASE_URL`.
2. Запустите базу данных:
   ```
   docker compose up -d
   ```
3. Установите зависимости:
   ```
   pnpm install
   ```
4. Создайте таблицы в базе:
   ```
   pnpm db:migrate
   ```
5. По желанию — заполните базу 1000 тестовыми контактами вместе с историей мести: к каждой заметке с датой — такая же запись. Примерно у четверти контактов задана частота «Как часто припоминать», так что на главной сразу есть блок «Пора мстить», а примерно 60 % людей разложены по пяти стартовым группам, по одной-три группы на человека (сработает, только если база пустая; существующие контакты не трогает):
   ```
   pnpm db:seed
   ```
6. Запустите приложение:
   ```
   pnpm dev
   ```
   и откройте http://localhost:3000

## Обычный запуск

Если всё уже настроено:

```
docker compose up -d
pnpm build
pnpm start
```

Приложение откроется по адресу http://localhost:3000. Остановить — `Ctrl+C` в окне, где оно запущено. Остановить базу — `docker compose stop` (данные сохраняются).

Приложение доступно только с этого компьютера: входа по паролю нет, поэтому оно не открыто для других устройств в сети.

Нужен запущенный Docker. Команда сама собирает приложение и запускает его на http://127.0.0.1:3100 со своей базой `<имя базы>_e2e_test` (например, `personal_crm_e2e_test`), которую создаёт заново при каждом запуске; основная база не меняется. Перед первым запуском один раз установите браузер для тестов: `pnpm exec playwright install chromium` |

## Выкатка на сервер

Новая версия выкатывается сама после `git push` в ветку `main`. Ход выкатки виден на GitHub во вкладке **Actions**: зелёная галочка — выкатилось, красный крестик — выкатка упала.

Что происходит после push:

1. GitHub собирает образ приложения и кладёт его в GitHub Container Registry (GHCR) с номером коммита в имени.
2. GitHub копирует на сервер файлы из папки `deploy/` и запускает `deploy/deploy.sh`.
3. На сервере скрипт скачивает образ, разовым контейнером из этого же образа применяет миграции базы и только потом запускает новую версию. Упали миграции — новая версия не запускается, работает старая. В логе Actions тогда будет строка `Migrations failed (code …)`: код ошибки и, если база их назвала, имена таблицы, поля и ограничения. Данных контактов в ней нет.
4. Скрипт проверяет, что `/health` отвечает 200. Не ответил — выкатка считается упавшей. Сам он ничего не откатывает.
5. После удачной выкатки на сервере остаются только текущий и предыдущий образы.

Сервер: `153.76.175.40`, папка `/opt/personal-crm`, войти — `ssh crm`. Приложение и база работают в Docker (проект `prod`), база — в отдельном контейнере со своим хранилищем. Наружу приложение открыто только через nginx.

Настройки сервера лежат в `/opt/personal-crm/.env` с правами 600, в git их нет. Какие строки там нужны — в `deploy/server.env.example`.

Проверить, что работает:

```
ssh crm curl -s http://127.0.0.1:3000/health
```

Ответ `{"status":"ok"}` — приложение работает и видит базу.

Откатиться на предыдущую версию (только вручную):

```
ssh crm 'bash /opt/personal-crm/deploy/deploy.sh "$(cat /opt/personal-crm/previous-image)"'
```

Откат меняет только версию приложения: изменения структуры базы, которые успела применить новая версия, остаются.

## Как устроено

- `src/app` — страницы: список контактов (`page.tsx`), карточка (`contacts/[id]`), сохранение и удаление контактов (`contacts/actions.ts`) и записей о мести (`contacts/interaction-actions.ts`)
  - главная показывает список по страницам: по алфавиту, по 50 человек, под списком переключатель «‹ 1 … 4 5 6 … 20 ›» и подпись «Страница 5 из 20». В браузер уходит только одна страница, а не весь список
  - справа от счётчика — выбор «По: 25 · 50 · 100». Нажатие запоминается в этом браузере (cookie `contact-list-size`, в ней только число); ссылка с `?size=` показывает своё количество, но выбор не меняет. После смены количества открывается страница, где стоит первый контакт текущей страницы
  - поиск «Найти по имени» ищет по всем контактам на сервере, в базе: все слова в любом порядке, «ё» = «е». Результаты появляются через 0,3 с после последней нажатой клавиши и тоже идут по страницам
  - страница, поиск и количество — в адресе: `/?page=3`, `/?q=петров&page=2`, `/?page=3&size=100` (группа тоже, см. ниже). Первой страницы и количества 50 в адресе нет. Неправильный номер открывает первую страницу, слишком большой — последнюю, неправильное количество не учитывается
  - под заголовком «Косячники» — строка групп «Все · Аналитики · Друзья · …» и кнопка «Группы». Выбранная группа сужает и список (со страницами, поиском и счётчиком «12 контактов» / «Найдено: 3 из 12»), и блок «Пора мстить»; при смене группы открывается первая страница, поиск и количество остаются. Пустая группа показывает «В группе «…» пока никого нет». На телефоне группы прокручиваются вбок, на компьютере переносятся на следующую строку
  - группа — в адресе вместе со страницей, поиском и количеством: `/?group=3`, `/?group=3&q=петров&page=2&size=100` (в адресе номер группы, поэтому переименование его не ломает). Без `?group=`, с не числом или с уже удалённой группой показываются все. Выбор группы нигде не запоминается: главная, открытая заново без `?group=`, показывает всех
  - кнопка «Группы» открывает окно «Группы»: все группы по алфавиту с числом людей, поле «Новая группа» с кнопкой «Добавить» (или Enter), у каждой группы иконки «Переименовать» и «Удалить группу». Форма переименования и подтверждение удаления показываются внутри этого же окна, без второго окна поверх. Удаление группы людей не удаляет. Переименование и удаление группы не меняют дату «изменён» у людей
  - после «Добавить черта» открывается страница, на которой стоит новый контакт, с меткой «Новый»; группа и поиск при этом сбрасываются
  - «Весь список» в карточке и удаление контакта возвращают на ту страницу, с тем поиском, группой и количеством, откуда открыли карточку (запоминается во вкладке, `src/lib/list-return.ts`); карточка, открытая по прямой ссылке, ведёт на первую страницу
  - на главной кнопка «Добавить черта» открывает окно «Новый чертила»; отдельной страницы `contacts/new` больше нет, по этому адресу — «Контакт не найден»
  - на главной над поиском — блок «Пора мстить»: контакты с заданной частотой, которым ещё не мстили или с последней записи о мести прошёл срок (неделя — 7 дней, месяц, квартал и год — календарные, «сегодня» — по Москве). Сверху те, кому ещё не мстили, ниже — по сроку, при равном сроке — по алфавиту. Видно первых пятерых, остальные — по «+ещё N людишек». У каждого кнопки «Отомстил» (запись с сегодняшней датой) и «Простить» (сбрасывает частоту); на телефоне это иконки. Мстить некому — вместо блока карточка «Пока некому мстить» с грустным котиком
  - карточка открывается в режиме просмотра; у имени две иконки: «Редактировать» открывает окно «Редактировать контакт», «Удалить» спрашивает подтверждение (удаляются контакт, заметки и история мести; группы остаются, даже если в них больше никого нет)
  - в окнах «Новый чертила» и «Редактировать контакт» после «Откуда знакомы» — поле «Группы»: из списка можно выбрать несколько групп, выбранные стоят метками с крестиками (по алфавиту), а набранный текст сужает список. Если такой группы нет, в конце списка — пункт «Создать группу «…»» (Enter выбирает подсвеченный пункт и форму не отправляет, Ctrl+Enter сохраняет). Новая группа появляется в базе только вместе с контактом: «Отмена» её не создаёт. Контакт и его группы сохраняются одной операцией: либо всё, либо ничего. Если выбранную группу удалили, пока окно было открыто, контакт сохранится без неё
  - в карточке после «Откуда знакомы» — строка «Группы» метками по алфавиту (все, сколько бы их ни было), без групп — «не указано». В списке под «Откуда знакомы» у человека видны до трёх меток и «+N» для остальных; длинное название обрезается, полное видно при наведении. «изменён» меняется при сохранении в окне «Редактировать контакт», в том числе если поменяли только группы
  - под именем — строка «мстили 24 октября 2026» или «Пока не мстили»; в списке полей — «Как часто припоминать» (раз в неделю, месяц, квартал, год или «Не задано»; задаётся в окнах «Новый чертила» и «Редактировать контакт») и раздел «Последняя месть»: последняя запись, ссылка «Вся история» и кнопка «Отомстил»
  - кнопка «Отомстил» открывает окно «Отомстил» с датой (по умолчанию сегодня по Москве) и текстом; «Вся история» открывает окно «История мести»: там же, внутри одного окна, добавление, изменение и удаление записей
  - записи о мести не меняют дату «изменён» у контакта; смена частоты (в том числе «Простить») — меняет
- `src/components` — части интерфейса: список с поиском, переключатель страниц (`contact-pagination.tsx`) и выбор количества (`page-size-picker.tsx`), блок «Пора мстить» (`due-contacts.tsx`, `due-contacts-list.tsx`) и грустный котик (`cat-sad.tsx`), строка групп (`group-filter.tsx`) и окно «Группы» (`groups-dialog.tsx`), форма контакта и окна с ней («Новый чертила», «Редактировать контакт») с полем «Группы» (`group-picker.tsx`), кнопки у имени в карточке, раздел «Последняя месть», форма записи и окна «Отомстил» и «История мести»
- `src/db` — схема таблиц и подключение к базе: контакты (`contacts`, в том числе частота припоминаний `contact_frequency`: неделя, месяц, квартал, год или пусто — «Не задано») и история мести (`interactions`, записи удаляются вместе с контактом)
  - группы контактов: таблица `groups` (название; повторы база не пускает без учёта регистра и разницы «ё»/«е») и таблица связей `contact_groups` (кто в какой группе; человек входит в группу не больше одного раза). Связи удаляются вместе с контактом или группой, сам контакт и сами группы остаются
  - все запросы к базе идут через `runQuery` (`src/db/index.ts`). Если запрос не удался, в журнал приложения пишется `Database query failed: <запрос> (code …)`, например `Database query failed: createContact (code ECONNREFUSED)`: какой запрос, код ошибки и, если база их назвала, имена таблицы, поля и ограничения. Данных контактов, текста запроса и пояснений базы в записи нет. `code ECONNREFUSED` значит «база не отвечает»
- `src/lib` — запросы к базе, в том числе страница списка с поиском и страница нового контакта (`contacts.ts`), кому пора мстить (`keep-in-touch.ts`), группы: запросы и сохранение групп контакта (`groups.ts`), правила названия (`group-schema.ts`), логика поля «Группы» (`group-match.ts`), метки в строке списка (`group-badges.ts`), размеры страниц, разбор адреса и ссылки на страницы (`pagination.ts`), частоты и их подписи (`contact-frequency.ts`), проверка полей формы, форматирование (даты — по московскому времени)
- `drizzle` — миграции базы, в том числе разовый перенос истории мести из заметок (`0002_copy_interactions_from_notes.sql`): строки заметок, начинающиеся с даты, стали записями; сами заметки не изменились; `0004_create_groups.sql` создаёт таблицы групп, а `0005_add_default_groups.sql` добавляет пять стартовых групп — «Аналитики», «Друзья», «Знакомые», «Семья», «Теннис»: в них никого не кладёт, прежние контакты остаются без групп
- `scripts` — генератор тестовых контактов с историей мести, частотой припоминаний и группами и запуск миграций в рабочем образе
- `src/test`, `vitest.config.ts` и файлы `*.test.ts` рядом с кодом — автотесты (Vitest). Перед запуском создаётся пустая база `<имя базы>_test` с миграциями, перед каждым тестом её таблицы очищаются. Если имя базы не кончается на `_test`, тесты отказываются работать, так что основную базу они не затронут
- `e2e` и `playwright.config.ts` — сквозные тесты (Playwright) в браузере Chromium: главный сценарий из `specs/01-продуктовая-идея.md` (`e2e/main-scenario.spec.ts`). Перед запуском создаётся пустая база `<имя базы>_e2e_test` с миграциями, потом собирается и запускается приложение; перед каждым тестом база очищается, и тест сам кладёт в неё нужных людей. Упавший тест оставляет в папке `test-results` снимок экрана и запись всех шагов; открыть запись — `pnpm exec playwright show-trace <путь к trace.zip>`, отчёт целиком — `pnpm exec playwright show-report`
- `Dockerfile` — сборка образа приложения
- `deploy` — файлы выкатки, которые копируются на сервер
- `.github/workflows/deploy.yml` — автовыкатка после push в `main`

Данные читаются и сохраняются только на сервере; браузер к базе напрямую не обращается.
